# ProvisionalClaimRegistry

This directory contains a **non-authoritative, first-pass** extraction of semantic-claim candidates from the five frozen Stabilizerness demo papers. It is intentionally separate from accepted `MathClaimIRRegistry`, `ScientificClaimRegistry`, and `ExternalRecordRegistry` records. Nothing here is accepted MathClaimIR.

## Layers

1. `occurrences.jsonl` records every detected `SourceClaimOccurrence` independently. Occurrences are never deduplicated. Each record pins the paper, canonical source artifact and SHA-256, exact 1-based inclusive line range, verbatim source lines, section path, span kind, speech act, provisional status, and reason codes.
2. `canonical-candidates.jsonl` contains deterministic preliminary semantic candidates. The filename means only that this is the candidate layer; it does **not** mean that semantic canonicalization has occurred. Exact normalized repeats may share a candidate, but every source occurrence remains present and referenced. Statement fields are typed but partial. A candidate either has assumptions/conclusion fields or an explicit unresolved payload. `EXACT` is reserved for a mechanically isolated claim body whose predicate is copied without interpretation; whole theorem/definition environments with partial predicates are `INTERPRETIVE`. An equation/context span is `MULTI_SPAN_DERIVED` only when an explicit derivation cue establishes the relation; otherwise it is an unresolved `EQUATION_CONTEXT_BUNDLE`. Unparsed display equations are also `UNRESOLVED`.
3. `modules.json` drafts `CanonicalClaimModule` boundaries with imports, assumption contracts, definitions, core claims, derived exports, an `unresolved_review_queue`, and limitations. Every candidate occurs in exactly one of those role lists.
4. `graph.json` contains candidate-only typed edges: definition prerequisite, scope assumption, claim premise, derivation, and equivalence/specialization/generalization candidates. Edges require substantive shared terms or typed-symbol overlap and carry those discriminative terms, occurrence evidence, and reason codes. Generic formatting/environment/reference commands are excluded. Adjacency alone creates no edge, and an internal biconditional or “special case” phrase is not a relation to the preceding candidate without explicit anaphoric language. Direction is always **earlier prerequisite/supporting candidate → later dependent candidate**. For relation edges, the target is the candidate described as a specialization, generalization, or equivalent reformulation of the source. It is **not a verified DAG**. Cycles and equivalence candidates require review and, when appropriate, quotienting.
5. `paper-delta.json` is a review-required draft pinned to commit `132b4ca17e098d37fa265b6bc42550845bc1dec5`, the corresponding accepted claim-file Git blob, preprocessing blob, and available source-anchor blobs. Its vocabulary is `reused`, `equivalent`, `specialization`, `generalization`, `new-to-registry`, `new-proof`, `new-relation`, and `unresolved`. Every row carries comparison evidence and reason codes. `baseline_record_refs` is populated only by an exact representation match or a unique conservative statement-level match after pinned project-macro expansion with discriminative shared terms. Only an exact representation match may receive `reused`; a conservative partial statement match retains its baseline link and evidence but remains `unresolved`. Coarse source-anchor overlap is location evidence only: it is retained separately in `possible_baseline_region_refs`, never counted as a candidate-to-claim link, and leaves the disposition unresolved. Semantic relation dispositions require explicit review evidence and baseline references. `new-to-registry` requires an actual registry-absence audit. **NEW_TO_REGISTRY means only absent from that fixed registry snapshot; it does not mean academic originality.**

All semantic labels are automatic and provisional. `REVIEW_REQUIRED` and low-confidence reason codes identify decisions that must not be promoted without review. This pass produced **1,648 occurrences → 1,645 candidates**, only three exact-repeat merges (candidate/occurrence ratio **0.998180**). This is almost no compression: semantic deduplication, quotienting, and genuine module compression have not yet occurred. The manifest records these compression statistics as well as linked-candidate and unique-baseline counts, statement-evidence method distributions, possible-region counts, and the maximum baseline links per candidate; possible regions are not included in link metrics. `Physlib` and `PhyslibAlpha` occur only as future-oracle markers; no alignment with either library is claimed.

## Extraction scope

The deterministic extractor reads every line of each listed canonical LaTeX artifact. The manifest pins SHA-256 hashes for this README and every schema file, and `--check` rejects missing or drifted static registry files without overwriting them. Before creating output, it loads every `PaperAgentRegistry` manifest and checks configured paper/path/hash, manifest paper/path/hash, and actual bytes as one invariant. It strips TeX comments for parsing while correctly retaining escaped `\%`; comment-only lines suppress a TeX newline and therefore remain inside a prose range, whereas true blank lines split paragraphs. Balanced-brace heading parsing handles nested commands and embedded `\label{...}`. The extractor tracks part/chapter/section/subsection hierarchy, joins multiline paragraphs, captures exactly configured theorem/definition environments (plus the controlled `*` suffix) and display equations, creates non-overlapping equation context bundles that never contain another display equation, and detects ordinary prose assertions. Stored source text is verbatim from the canonical file, not comment-stripped text.

The extraction parser deliberately favors recall over semantic precision. It does not expand `\input`, prove claims, infer academic novelty, or claim registry/library alignment. PaperDelta comparison alone applies the pinned preprocessing receipt's simple project-macro expansions to make source and accepted statements auditable on the same notation basis.

## Validation

From the repository root:

```bash
python3 -m unittest tests.test_provisional_claim_extractor
python3 tools/extract_provisional_claims.py
python3 tools/extract_provisional_claims.py --check
```

The unit tests cover static README/schema integrity, cross-artifact procedural validation, exact-once module and delta coverage, the PaperAgent/source hash invariant, comment handling, escaped percent signs, comment-only and true-blank paragraph behavior, balanced nested headings (including frozen regression lines), equation discourse bundles, theorem-like environments, ordinary prose claims, conservative graph direction/evidence, deterministic IDs/hashes, 1-based lines, source-text fidelity, pinned-baseline linkage, negative JSON Schema cases, and reference integrity. `--check` regenerates into a temporary directory and byte-compares every generated artifact.
