# v0.4 当前状态：框架已搭好；第一次真实测试（quant-ph 50 篇，只有确定性层）已跑完并载入 Neo4j

## 结论（2026-09-26）

v0.4 由**合同（schema）、宿主代码、Neo4j 文件和一个可点击的说明页**构成，合成数据上的离线检查全部通过。2026-09-26 按负责人的要求做了**第一次真实测试**（记录：[runs/quant-ph-sample-20260926](runs/quant-ph-sample-20260926/INDEX.md)）：

- 从 arXiv 元数据快照（Kaggle 第 304 版的 Hugging Face 副本，2026-09-19）中，按种子随机顺序抽取 quant-ph（2015–2025）理论论文，考察 80 篇，得到 50 篇合格；
- 只运行了**确定性层**（从证明里的 `\ref`、`\cite` 建依赖），建成 151 个增量，主机不变量检查 0 项发现；
- P-1 关口决定 **GO_WITH_EXPANSION**：样本论文之间没有共同引用到 3 篇以上的 work，也没有互相引用；
- 投影载入本地 Neo4j 2026.09.0，状态 READY，14 个审计全部 0 行；这是 v0.4 的 Cypher 第一次由真实 Neo4j 执行。
- 第二轮 [runs/quant-ph-claude-agent-20260926](runs/quant-ph-claude-agent-20260926/INDEX.md)：按负责人要求，用当前 Claude 模型的子 agent 代替外部模型依次做 S6、EXPANSION、S7。只做了第 1 篇就应负责人要求暂停：3 个窗口里 2 个因“共用出处”规则被拒（原指令只写了这条规则的一半），而且按这个速度一次一个 agent 做完 50 篇约需 90–110 小时。
- 单个 claim 的依赖链页面 [viewer/claim-view.html](viewer/claim-view.html)：数据实时从 Neo4j 读取，沿用 chain-build 的形状和颜色，论文边界画成虚线框，穿出框的曲线就是跨论文依赖；未测试（V04-37）。

仍**没有做过**的事：没有调用任何模型（S6 抽取、S7 匹配、自动评审和 LLM 检索都未运行），所以 P0 关口还没过；没有形式化任何定理，没有运行 Lean。测试给出的数字只说明确定性层在这 50 篇上的产出，不说明方法的精度或召回。

**测试最重要的发现**：确定性层在 quant-ph 上很薄。50 篇里只有 14 篇有定理类环境，只有 11 篇产生依赖（共 135 个 junction），其余 36 篇是只有公式推导的物理论文，要靠 S6 模型抽取才能建依赖；论文之间也还连不起来，需要 S7 匹配和 EXPANSION（纳入被引论文）。

第 3 版修订落实了负责人本轮的决定：

- **同等完整抽取（EQUAL_FULL）**：每篇被接受的论文都用同一个抽取策略；撤销了“优先抽取”和“审计臂”。
- **语料更宽**：只有公式推导、没有定理环境的物理论文（包括结合实验的理论推导）也能纳入；引用的论文（EXPANSION）和 LLM 检索找到的论文（DISCOVERY）可以加入，但计数时与随机样本分开（`count_basis`）。
- **全自动判断**：不再需要人工标注。抽取质量由一组盲评的模型评委判断，用“诱饵”测出评委被骗的比例，再给出保守的精度下界（AUTO_EVAL_V1）；每道关口都是 S0 时预先写定的规则，由宿主自动执行。人工标注降为可选的抽查。
- **成本**：新增“整篇上下文”抽取模式（WHOLE_PAPER_FOCUS），整篇论文作为同一个可缓存的提示前缀；`cost.py` 按官方价格文件预测费用和时间。按 MiMo-V2.6-Flash 现价，一万篇约 $638（实时）/ $319（Batch），缓存不命中时 $2,038 / $1,019（ESTIMATED，见 spec §1.1）。

**按两份独立静态审阅所做的修正（2026-09-26）**，要点如下（术语：“层”（stratum）指抽样时按来源分开统计的一组条目，例如同一方法、同一版本、同一种用法的腿）：

- **P0 关口不再相信存档的结论**：它按清单里写定的规则，从计数重新算每一层的精度下界；计划、报告、成本预测若被改过（编号不再等于内容摘要）就拒绝；报告必须恰好覆盖样本的每一层。
- **版本分开**：每一层记下产生它的方法版本；只有语料规定的抽取版本能让 MODEL_EXTRACTION 通过，对照版本只作比较。
- **诱饵更像真的**：诱饵与被替换的前提同类（文献条目换文献条目、公式换公式、环境换环境）；排除证明里引用到的、包住引用目标的、反过来引用结论的、以及与结论论文有引用关系的论文；每条诱饵规则分别算误判率，取最差的一条。
- **引文要够长**：USED 必须附至少 12 个字符的原文，重复引文最多扩展 80 个字符。
- **成本与本次运行挂钩**：价格文件由程序自己读并算摘要；可用提示构造器实测的每篇调用数和前缀；为 S7、评审、检索预留预算；P0 要求论文数不少于目标、大小为实测、参数中没有 ESTIMATED。更正了一处错误说法：整篇上下文模式的 token 数其实随论文大小 S 的平方增长，只是重复的前缀按缓存价（1/50）计费。
- **读不到的源文件记为“无法判定”（UNDETERMINED），不再算作“不合格”**；覆盖核对使用账本的终止状态；模型回答被宿主检查拒绝时可重试到次数上限；PRIMARY 分析必须同时给出 P0 决定、语料清单和完整的覆盖报告。

## 已知限制

- **自动评审的假设**：诱饵确实未被使用；评委在真实未用前提上的误判率不超过最差诱饵规则上的 κ 倍（默认 κ = 2）；正对照（证明里 `\ref` 过的前提）比一般的腿容易，所以点估计偏乐观。下界本身不依赖评委的灵敏度。评委没有按训练截止日期分层（MiMo 的截止日期未知）。这些都要在 P0 试点中实测（V04-24）。
- **依赖主题数**用 arXiv 分类（主分类加交叉分类），分不开同一分类内部的不同主题；以后可以用文献耦合聚类。
- **成本参数**里每字节 token 数、输出长度、一次通过率是在 GPT 模型的记录上测的；MiMo 的分词、缓存命中率、思考长度都未测（V04-25）。论文大小只有 8 篇、且是沿引用链选的。
- **整篇上下文模式的已知缺口**：没有任何环境或公式的源文件不单独成焦点，只作为上下文；只写在这类文件散文里的结论不会被抽取。
- 已实现 S1 获取（`host/acquire.py`：元数据快照帧、版本规则、从 export.arxiv.org 限速获取、结果分类），并在测试运行中用过；它的单元测试尚未编写（PENDING_TESTS V04-33）。
- 主文件选择与编码：测试中 80 篇有 7 篇因多个可编译的 `.tex` 而“主文件不唯一”，3 篇主文件不是 UTF-8；是否改规则待决定（V04-36）。
- 未实现：Crossref / OpenAlex 适配器、S6/S7/评审/检索的真实模型派发、通用的命令行运行器（测试用的是一次性脚本 `runs/quant-ph-sample-20260926/run.py`）、v0.4.1 陈述聚类。
- `match_coverage` 目前总是 null，因为还没有 S7 尝试记录。
