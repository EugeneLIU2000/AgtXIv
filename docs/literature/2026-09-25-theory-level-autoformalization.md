# 论文评估：理论级自动形式化（Theory-Level Autoformalization）

  *Theory-Level Autoformalization: From Isolated Statements to Unified Formal Knowledge Bases.*

## 1. 结论

1. 这是一篇纲领性的论文，没有提出系统，也没有新实验。核心主张：自动形式化不应再逐条翻译孤立的定理，
   而应把一个领域的公理、定义、记号、引理、定理、证明、战术连同它们的依赖，形式化成一个连贯的库。
2. 对 AgtXIv 的意义：AgtXIv 在做论文所呼吁的事情的一个**文献驱动**版本——不是给定一个理论去形式化，
   而是从研究论文出发，用依赖图去**发现**需要形式化的那部分理论，并记录每一步的来源与不确定性。
3. 论文最能直接改进 AgtXIv 的三点：
   - 等价判断必须声明允许多少隐含计算（“等价片段”），否则不同判断不可比；
   - 定义层（论文的 L0/L1）应当单独处理，并跨文献聚类同一概念；
   - 评测要满足三条：包含背景理论、对专家判断报告精度与召回、控制数据泄漏。
4. schema v0.4 的新工作流（先在大量同领域论文上建依赖图，再用图分析找出早期、被广泛依赖的基础
   claim）可以看作用经验方法**从文献中估计论文所说的“形式化之塔”的底层**：估计对象是抽样框中
   “本流程可处理且符合资格”的论文总体，而不是整个领域。

## 2. 论文要点

### 2.1 “理论级形式化之塔”

论文用 Lean 中的欧氏几何体系（SystemE）说明，一个理论分四层：

| 层 | 内容 | 例子 |
|---|---|---|
| L0 | 公理化原语：基本类型、基本关系、公理 | 点、线；“同侧”关系 |
| L1 | 派生定义 | 角、线段、三角形 |
| L2 | 工具：记号、引理、战术 | 自定义证明战术 |
| L3 | 目标定理及其证明 | 勾股定理 |

现有最好的方法在 L3 语句上约 71.4%，但前提是 L0–L2 已由人写好；没有方法尝试自动生成下面几层。

### 2.2 为什么需要理论级

- 真实项目本来就是理论级的：Kepler 猜想形式化用了 11 年，大量时间花在定义与引理上。
- 在 Mathlib 覆盖不到的领域，“写出陈述”本身就要先建理论。
- 重大发现依赖新抽象（群、范畴、平展上同调）。

### 2.3 四个开放挑战

1. **等价检查**：人工参考答案本身不可靠（ProofNet 约 31.8%、PutnamBench 约 8.6% 的错误率）；
   没有既可靠又覆盖广的检查器。大模型评判没有保证；字面匹配过严；纯逻辑等价缺背景理论；
   定义展开判断不了 `m+0` 与 `0+m`；不加限制的命题等价则“所有真命题都等价”。折中是只允许计算性
   战术的双向证明（BEq+：精度 98.0%、召回 48.3%；纯定义等价：精度 100%、召回 30.9%），
   但两边都能被战术直接证出时仍会误判。更根本：等价是主观的，取决于允许的隐含计算量，
   任何检查器都必须声明这个阈值。
2. **分层分解与抽象学习**：现有“半理论级”项目依赖专家手写蓝图（引理与定义的依赖图）；
   自动分解方法只处理高中数学、浅层图、一次一条语句。抽象学习（如 DNA：从语料抽共同概念、
   建概念依赖图、形式化为可复用定义）只处理组合型定义，没有人处理公理化定义。
3. **Lean 之外的低资源语言**：SMT-LIB、Ivy、SVA、Cypher/CodeQL/Cedar 等。
4. **多模态输入**：示意图、时序图、图片。

### 2.4 三个提议

1. **理论级基准**：包含背景理论；用可靠等价检查并报告相对专家判断的精度与召回；防止数据泄漏。
   近期做端到端案例，度量有无 AI 辅助时形式化一个新理论所花的时间与专家工作量。
2. **通用模型加验证反馈**，而不是微调专门模型（在 Mathlib 之外的 LeanEuclidPlus 上，
   Goedel-Formalizer-V2 为 0.0%，其底座 Qwen3-32B 为 20.6%）。
3. **共同中间表示**（Lean 是候选），再转译到各领域语言。

### 2.5 附录 B：证明自动形式化 ≠ 定理证明

前者要忠实翻译一份特定证明的结构（如 ProofFlow 把证明建成依赖图、每步作为中间引理）；
后者只要找到任意证明。理论级不要求证明一切可证之事：没有非形式证明的真命题是定理证明的任务。

## 3. 与 AgtXIv 的对照

### 3.1 schema v0.3 相对论文的意义

- **论文没回答、v0.3 回答了的问题：范围怎么定。** v0.3 以一条研究结论为根，沿证明依赖与文献引用
  确定需要形式化的最小子理论，在库已覆盖处停下（“查询驱动的理论级形式化”）。
- **文献维度**：理论分散在跨越几十年的多篇论文中（Hurwitz 1898、Lovász 1972、Newman 1932 的勘误）；
  v0.3 的依赖跨论文、带字节级来源与勘误。
- **条件化的部分库**：底层缺失时用显式 Prop 前提而非公理，证书只说“在 P₁…Pₖ 下成立”。
- **比等价检查更完整的可信度账本**：即使陈述等价，库仍会在前提无法满足、定义的垃圾值语义
  （`IsPerfect` 缺有限性条件的真实例子）、声明未真正组合这三处出错。
- **落后之处**：没有等价检查器；底层定义与 Lean 链由代理手写；自动证明器只有 1 次真实调用；
  没有相对专家判断的精度与召回；记号与战术（L2）未处理。

### 3.2 schema v0.4 相对论文的意义

- v0.4 在大量同领域论文上建立 claim 依赖图，再用图分析选出早期、被广泛依赖的 claim。
  它把论文的“塔”从一个理论的设计问题，变成一个可以在文献上**测量**的问题：
  在抽样得到的论文总体中，哪些定义与结果被最多其他论文的 claim 所依赖。
- 论文的挑战 2（蓝图生成）与 v0.4 Stage 1 相关但不相同：v0.4 记录的是**候选**前提集合，
  没有检查这些前提是否足以推出结论，因此不是论文意义上的蓝图（后者是经专家拆分、每步可证的细粒度图）。
  论文的抽象学习（跨语料的概念）对应 v0.4.1 的概念聚类。
- v0.4 的输出是“提名”（nomination）而不是结论：图上排名靠前不等于正确、不等于已审阅。
