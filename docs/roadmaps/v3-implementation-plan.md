## 1. 实施原则与完成判据

先固定“什么可以被宣称”，再实现生产与复用。最先做的可运行结果应能诚实表示一个有缺口的论证，并正确拒绝不匹配的复用；不能先做一个把所有节点画绿的展示。

每项任务须提交五样东西：版本化产物、精确输入、适当的正反向验收证据、独立审阅结果、已知边界。写出 schema、文件成功生成、模型自报通过，均不能单独宣布功能完成。

下文“负责”是责任角色，不是已分配人员。“依赖”说明逻辑前置，不代表必须串行完成全部开发。章节内方框均为未来任务，只有按该任务出口验收后才勾选。日期与工期应在资源、模型预算和人工审阅能力明确后排定，不用虚构周数掩盖依赖。

V3 完成至少需要一个冻结的小领域集合，包括前置论文与后续论文，并出现以下真实记录：整篇范围清点、论证中间层、六轴评估、符合选定标准的形式与科学核查、相对基准的贡献、独立发布与逐条入库、一次成功复用、一次拒绝复用、一次局部修订以及可见的未解决前沿。

## 2. 总体依赖与工作流

```text
P0 设计基线
  → P1 最小数据契约
      → P2 来源/主张/范围
          → P3 论证中间层
              → P4 形式与科学核查
                  → P5 贡献与复用
                      → P6 审计/发布/知识入库
                          → P7 增量生命周期与查询
                              → P8 迁移和扩展准备
```

可并行的工作：P1 的证据接口确定后，科学语义与经验/计算记录设计可先开展；P3 的导出适配、身份边界和依赖检查可分工；P4 的 Lean 工作者与科学评估者可并行；P5 的基准设计可用候选结果提前进行，但不能提前发布贡献判断。

上述顺序是集成验收顺序。后面的存储、界面和接口可以提前做设计，但不应反过来规定科学对象必须如何简化。

## 3. P0：冻结设计与评估边界

**目标：** 明确 V3 到底建设什么，以及哪些状态不能被混用。

**负责：** 项目维护者、科学设计审阅者、reader。

**依赖：** 本次设计提案。

- [ ] **P0.1 版本与权威边界。** 明确 V3 提案到版本规范的采用流程；记录当前 Charter 状态，正式适用时绑定批准提交。交付 V3 版本决定、旧版解释规则和不升级约束。验收：不修改旧 schema/历史评估；没有把文档批准等同科学结果发布。
- [ ] **P0.2 处理标准。** 固定 SOURCE_MAP、ARGUMENT_AUDIT、FORMAL_SUPPORT 的必要工作、成功义务、允许的未解状态及经验/计算附加要求。交付规则表。验收：区分“义务有处置”与“必须成功的义务已满足”，禁止事后缩小分母。
- [ ] **P0.3 角色与独立性。** 明确生产、论证审阅、形式对齐、科学评估、论文审计、认证、准入的身份约束。交付角色矩阵、可见输入政策和冲突处理。验收：同 actor 换名字不能自审；同模型相关性如实披露；领域人员介入条件明确。
- [ ] **P0.4 固定评估集合。** 从已有结果中选择一个小领域的前置/后续论文与正反向案例；记录各素材的旧状态与证据缺口。交付集合清单、来源版本和各核查分母。验收：覆盖错误范围复用、未证依赖、相邻但独立的证明、已知反例及缺失证据；不视旧结论为未经复核的标准答案。
- [ ] **P0.5 Charter 对照。** 对八原则和七项版本责任逐条写设计覆盖、实施状态、未实现部分和验收引用。交付 V3 对照表。验收：不会以“三个旧轴可以概括六个新轴”规避冲突；贡献变化成为必需产物。

**出口：** 读者能在不读 schema 的情况下说清“输入、产物、可复用部分、未解决部分、谁有权作何种判断”。若这些仍混淆，不开始扩展自动调度。

## 4. P1：最小记录契约和跨记录约束

**目标：** 建立足以支撑主流程的记录，而非一次性创建大量空注册表。

**负责：** 契约实现者、科学语义审阅者、独立代码审阅者。

**依赖：** P0。

- [x] **P1.1 精确身份和封套。** 复用经核实的现有字节哈希/规范化机制，定义 V3 schema、规则、生产者与输入引用。交付引用类型、封套、规范化向量和 resolver。验收：错误类型、旧哈希、重复身份、浮动 latest、缺字节均不能满足精确引用；原始字节与规范化记录哈希分开。**完成范围：本地契约机制，见执行状态；不代表机构身份或科学认可。**
- [x] **P1.2 六轴 Assessment。** 定义适用性、评估结果、执行处置、证据方法、目标和独立性；评估与命题内容分离。交付六轴契约与状态投影。验收：构建失败不等于反例；未运行不等于不适用；同一目标允许冲突评估并存；source/数学/形式/科学不自动升级。**完成范围：契约及提供记录集合内的只读投影；真实科学证据验收属于 P4。**
- [ ] **P1.3 清点与范围。** 定义计划、发现、独立冻结、义务与处置、新范围版本。交付契约和变更规则。验收：每个固定义务只有一个当前处置，所有历史尝试可追溯；漏项修复产生新范围；不能删掉失败项以满足标准。
- [ ] **P1.4 论证与交接接口。** 定义 ArgumentNode、InferenceStep、AssumptionContext、Challenge、ArgumentSnapshot、MathClaimIR 与 FormalizationPacket。交付字段语义与最小正反例。验收：共同前提不变成分别蕴含；树包含关系不冒充依赖；未解除假设不能逸出范围；交接版本不自带认可状态。
- [ ] **P1.5 知识、关系与贡献接口。** 定义 KnowledgeSnapshot、ReuseDecision、BaselineSnapshot、ContributionDelta、FrontierItem；早期只实现本流程必要字段。验收：每条贡献有基准及见证；关系方向明确；原文主张、证明方法和科学含义可分别引用。
- [ ] **P1.6 权威与快照依赖。** 固定产物清单→审计→认证→聚合包，以及前后知识快照→入库回执的无环身份关系。交付依赖示意及校验规则。验收：无自引用哈希循环；review 绑定精确对象，变更后不沿用旧批准。

**出口：** 一组人工构造的正反向记录能够说明每个关键边界。此阶段的结构校验不代表来源正确、独立身份真实或科学已获支持。

## 5. P2：精确来源、整篇清点与主张卡

**目标：** 把“作者究竟说了什么”整理为可复核输入。

**负责：** 来源实现者、主张生产者、独立来源/范围审阅者。

**依赖：** P1.1—P1.3。

- [ ] **P2.1 来源取得与隔离。** 建立 arXiv 精确版本、源压缩包、PDF、附属材料的来源快照；依据既有采集规范逐项复用。验收：版本变化、材料缺失、权限/许可问题单独记录；压缩包路径越界、源执行和资源耗尽受限。
- [ ] **P2.2 结构与活动内容。** 保存 TeX include、宏展开、附录、图表和正文关系，或 PDF 页面与提取映射。验收：被注释或未包含的内容不伪装为已发表断言；来源不可解析时保留阻塞。
- [ ] **P2.3 全文主张发现。** 先粗粒度发现，再按处理标准细分承重项；保存未分类项、非主张段落及其原因。验收：主张清单覆盖约定的全文分母，不只覆盖当前问题命中的段落。
- [ ] **P2.4 原文主张与组件对应。** 保留条件、量词、系统、语气、归属和比较基准；每个组件归到数学、科学语义、证据或未解决类别。验收：不得静默丢失任何原文含义，系统新推导不归给作者。
- [ ] **P2.5 修订与范围扩展。** 对提取遗漏生成修订，对新承重项生成新范围，对新增原文外条件生成独立命题。验收：三种情况可区分，旧主张与旧范围均保留。
- [ ] **P2.6 独立冻结。** 审阅者检查来源覆盖、关键条件和处理标准后冻结范围。验收：提取者不能自己用“完整”标签批准；未知项仍在分母中。

**出口：** 无论后面能否证明，读者都可定位每条主张及其真实限定条件。附录遗漏和条件遗漏必须进入验收，不只检查 JSON 能否解析。

## 6. P3：vibefeld 中间层

**目标：** 稳定获得完整、可归属、可继续审阅的数学论证记录。

**负责：** 适配器实现者、论证提出者、独立论证审阅者、安全审阅者。

**依赖：** P1.4、P2。上游核实见[接入说明](../architecture/v3-vibefeld-integration.md)。

- [x] **P3.1 固定上游协议。** 锁定 vibefeld 提交、导出版本、能力与适配器版本；记录 README 与代码差异。验收：不支持的事件/版本明确拒绝；不依赖浮动 main 或不存在的 Lean exporter。**完成范围：本地固定协议与离线适配机制，35 类事件、35 份源文件字节 pin 和 3 份协议 schema；不代表真实上游执行、受控命令或科学认可。见[机制说明](../architecture/v3-local-mechanisms.md)与[执行证据](v3-execution-status.md)。**
- [ ] **P3.2 完整快照导入。** 同时绑定 ledger、graph、scope、context、定义、externals、validation dependencies、完整异议及身份映射。验收：仅 graph.json 不足时明确缺失；目录搬迁不改变 V3 身份；导出与事件不一致被检出。
- [ ] **P3.3 稳定步骤与共同前提。** 将展示树、推理步骤、跨论文引用和不同证明方案分开。验收：同引理跨树复用、多前提联合推理、候选循环、归纳范围均可表示；不能用删边伪造闭合。
- [ ] **P3.4 实际身份与受控命令。** 在工作区外记录实际生产者、证明贡献者和审阅者；审核 `author`、`proof_author`、`validated_by` 映射。验收：同 actor 换名字、缺身份、过期内容审阅均无法取得独立审阅资格。
- [ ] **P3.5 异议生命周期。** 固定异议目标版本、回应、独立解决/撤回和未解决状态；设置资源及无进展阈值。验收：回复不自动解决，反驳不自动扩大到整篇；循环无进展能停止并给出下一步缺口。
- [ ] **P3.6 完整依赖影响。** 沿引用、定义、局部假设和证明方案计算影响，不仅沿树传播 taint。验收：上游 clean 但引用未证依赖仍阻塞相关支持；一个失败证明不污染独立证明。
- [ ] **P3.7 归档和义务守恒。** 删除、归档或替换节点须解释原必要义务如何被满足或合法移除。验收：即使新版树已不引用该步，也无法靠删除引用消除旧冻结义务。
- [ ] **P3.8 状态导入与独立评估。** `validated` 先作为 reported acceptance；身份、范围、上下文与依赖合格后才可形成审阅证据。验收：admitted 不变成知识准入，closed 不变成数学支持，clean 不变成公理审计通过。

**出口：** 能保存并独立审阅一次包含外部依赖、异议、局部假设和未解决步骤的调查；后续可精确重建同一版本。执行接入说明中的 VF-01—VF-13 验收，未通过项逐条保留。

## 7. P4：形式证据与科学证据

**目标：** 将论证交接给 Lean，并与科学语义、经验和计算证据分开评估。

**负责：** 形式化生产者、独立检查进程、对齐审阅者、领域评估者。

**依赖：** P2、P3。

- [ ] **P4.1 形式化交接。** 固定对象、量词、单位/约定、定义、前提、结论、近似误差、依赖与残余科学语义。验收：无身份的局部文件或漂移的外部定义不能满足输入；交接后改条件产生新版本。
- [ ] **P4.2 优先复用已有声明。** 先检索已有 Lean 包与声明，再匹配对象和前提，最后生成必要的局部证明。验收：名字相同或文本相似不能直接导入；形式包版本、命名空间和适配证明明确。
- [ ] **P4.3 独立形式检查。** 在固定环境重查目标声明与传递依赖，记录构建输入、公理及允许的信任机制。验收：sorry、目标变公理、额外未许可公理、遗漏目标构建均不能通过；生成者自报日志不能代替独立结果。
- [ ] **P4.4 独立对齐。** 实现源→论证/交接、交接→Lean、源→Lean 三种对照；反向解释者不先看预期答案。验收：量词顺序、定义替换、前提增强和结论弱化被区分；第三种对照不能复制前两份判断冒充独立。
- [ ] **P4.5 保留替代证明。** 分开 original/reconstructed/repaired/alternative 证明路径和归属。验收：可以表达“结论被独立证明，原文方法仍有缺口”；不能自动确认方法贡献。
- [ ] **P4.6 科学适用性。** 记录数学对象到模型/系统/可观测量的对应、单位、边界条件、近似与有效范围。验收：固定窗口/共同旋转窗口、纯态/混态、有限/无限维等条件不匹配时拒绝该用途复用。
- [ ] **P4.7 经验与计算证据。** 分别记录经验数据/误差/方法与计算输入/环境/种子/比较规则；标明承重或仅示意。验收：复现成功不升级经验支持；没有数据不写“不适用”；随机计算按预先规定的容差或统计标准比较。
- [ ] **P4.8 六轴投影。** 绑定各轴精确目标、证据、方法和条件，保留互相冲突的评估。验收：形式声明已证但对齐失败时，源主张不会获同样支持；物理假设未获支持时，条件数学定理不会被改判为数学失败。

**出口：** 对选定的形式目标有真实形式证据与独立对齐；对其余目标有标准允许的处置。经验或计算未实现的能力须作为明确缺口，而非通过结构校验伪装成核查结果。

## 8. P5：知识基准、贡献变化与复用

**目标：** 每篇论文处理后能说明对已有知识的具体改变。

**负责：** 依赖/关系实现者、贡献分析者、独立科学审阅者。

**依赖：** P3、P4；基准设计可提前开展。

- [ ] **P5.1 基准快照。** 冻结既有知识条目、范围、构建方式、检索覆盖与局限；区分作者自述基准与系统比较基准。验收：结果出来后不能偷偷换基准；无相关旧结果仅报告有界未发现。
- [ ] **P5.2 关系见证。** 对等价、特例、推广、限定、修正、反驳等关系记录精确端点、方向、条件和证据。验收：相似检索不能自动产生认可关系；数学等价但科学含义不同的条目保留。
- [ ] **P5.3 逐条贡献。** 为新结果、新证明、方法、数据/计算、独立复核和反例产生 ContributionDelta。验收：每个变化可追到论文内容及基准；同定理新证明不记作新定理，也不丢为零贡献。
- [ ] **P5.4 用途限定复用。** 检查假设、对象、强度、范围、证据政策、环境和冲突，输出可用/有条件/拒绝/未知决定。验收：成功复用和相似但条件不符的拒绝案例均出现；缓存命中不授予资格。
- [ ] **P5.5 未解决前沿。** 把缺失来源、未证引理、模型歧义和冲突证据连接到受影响结论及下一步需求。验收：之后一次调查可从该记录继续，不重复已记录的无效尝试。
- [ ] **P5.6 基准敏感性与分母。** 对至少两个合理基准/粒度配置比较变化归类，列出进入与退出的条目；若没有第二个合理基准，说明限制。验收：不产生论文质量总分，未知值不写成零。

**出口：** 读者能看到“相对谁、改变什么、根据什么、还缺什么”。结果尚可为候选，正式发布需 P6。

## 9. P6：论文审计、发布与逐条知识入库

**目标：** 从生成结果到可公开复用记录建立独立、不可混淆的决定链。

**负责：** 论文审计者、机械认证服务、归档服务、知识准入审阅者。

**依赖：** P4、P5。

- [ ] **P6.1 精确候选包。** 构建来源、范围、主张、论证、证据、六轴、贡献和未解问题的固定清单。验收：引用可解、字节一致、义务与处置完整；遗漏问题不能靠摘要掩盖。
- [ ] **P6.2 论文审计。** 按依赖顺序检查精确候选包，绑定科学评估、冲突与范围，给出是否符合处理标准的建议。验收：审计者不生产自己正在评估的对象；退回修订后产生新候选和新审计。
- [ ] **P6.3 机械认证。** 核对身份、规则、精确字节、审计建议与发布绑定。验收：不重新作科学判断；陈旧审阅、身份重叠或任一必要检查失败则拒绝。
- [ ] **P6.4 不可变归档。** 保存包、审计、认证和事件检查点；定义签名/独立检查点的实际信任边界。验收：工作者不能覆盖正式快照；仅有可改写哈希链不能自称防篡改。
- [ ] **P6.5 逐条准入。** 明确来源断言、论证证据、条件定理、经验记录、反例、前沿等条目类别的门槛。验收：归档不等于入库；入库也不等于命题为真；不支持的类别保留而不伪造成功。
- [ ] **P6.6 原子快照事务。** 固定候选集合与入库前快照，逐项接受/拒绝/阻塞，创建新快照和回执。验收：集合处置无遗漏重复；并发冲突时重试新事务，不部分覆盖旧知识；失败不改变原快照。
- [ ] **P6.7 冲突保留。** 保留不同评估与命题两端；区分技术性 supersession 与科学 correction/refutation。验收：新版本不会删除旧反例，排名不会抹除有关反对证据。

**出口：** 一份按指定标准发布的论文包与一份逐条知识准入回执。包内可有被拒绝或未解条目，不能把它们全部投影成“已验证知识”。

## 10. P7：增量生命周期和人/agent 查询

**目标：** 证明知识积累确实帮助处理下一篇论文。

**负责：** 生命周期实现者、查询实现者、reader、独立回归审阅者。

**依赖：** P5、P6。

- [ ] **P7.1 第二篇论文复用。** 在相同处理标准下，从前一知识快照解析依赖，只执行剩余需要的工作。验收：至少有一条真实获准复用与一条条件不符被拒绝；记录节省的是哪项操作。
- [ ] **P7.2 按类型传播影响。** 处理采用新定义/环境、新反例、来源纠错、假设范围变化及新经验数据。验收：沿完整引用而非展示树追踪；独立证明和无关轴不自动失效；浮动 latest 更新不会篡改旧绑定。
- [ ] **P7.3 修订历史。** 新调查、新范围、新评估和新知识快照追加保存。验收：可回答当时依据及当前变化原因；历史通过不等于当前用途仍可用。
- [ ] **P7.4 只读查询。** 支持主张、依赖、冲突、贡献、证据和复用条件查询，每次响应绑定确切快照及政策。验收：查询不改变正式范围；无已发布结果时临时调查不混入正式结果。
- [ ] **P7.5 reader 页面。** 默认显示主要主张、依据、六轴边界、贡献与前沿；英文记录名放展开细节。验收：读者能准确解释一个条件结果与一个反例，且不会把界面颜色当整篇正确。
- [ ] **P7.6 公共 agent 接口。** 返回结构化记录与公开解释的对应关系，保留相关冲突双方和来源。验收：流畅摘要中的每个承重断言可点回记录；仅无来源总结不能替代数据返回。

**出口：** 处理后续论文时能复用已经核查的工作；一次故意引入的依赖变化只触发相关部分重查。成本比较保持任务范围、证据标准与环境可比。

## 11. P8：迁移、评价与生产化取舍

**目标：** 在完成小范围科学闭环后决定扩展，而非用基础设施数量代替效果。

**负责：** 迁移实现者、评估者、维护者及独立审阅者。

**依赖：** P7。

- [ ] **P8.1 小批旧数据适配。** 选择 V1 bridge、V2 assessment、现有 Lean 记录和一个研究用假定记录，新增精确绑定。验收：原哈希和语义不改；三个旧轴不自动补六轴；缺历史事件不伪造。
- [ ] **P8.2 文档和消费者迁移。** 更新旧入口引用、客户端字段和状态解释，保持旧版可读。验收：新客户端识别旧契约，不用 V3 规则重新命名旧结论。
- [ ] **P8.3 价值评估。** 在固定集合比较直接形式化与中间层审阅的目标漂移、假设遗漏、返工、审阅负担及成本。验收：报告失败和置信限制，不仅报成功率；无对照时不宣称改善。
- [ ] **P8.4 复用评估。** 比较同等核查标准下有/无知识快照的重复工作量。验收：节省有确切任务对应，不能以少检查来冒充效率提升。
- [ ] **P8.5 生产化决定。** 根据实际吞吐、权限、归档、许可和并发需要决定数据库、队列、服务拆分、签名与运维。验收：每项新增设施有实际瓶颈或信任需求；生产上线单独评估。
- [ ] **P8.6 版本完成审阅。** 更新 Charter 对照与 V3 覆盖矩阵，列所有未来能力和限制。验收：没有重大未处理的错误升级、冲突遗漏或来源/范围错配；未实现能力不因文档齐全而勾选。

**出口：** 可解释的 V3 完成报告、迁移样本及扩展决定。完整多领域部署不属于本轮设计默认授权的实现工作。

## 13. 工作量控制与暂不优先的事项

优先控制论证和自动形式化的无限展开：按任务冻结预算，缓存精确成功/失败记录，把已知缺口列入后续队列；不要反复用不同措辞让相同模型自我投票。

在 P0—P4 不优先做：训练新的通用模型、全 arXiv 扫描、图数据库替换、复杂排名、论文质量评分、全局新颖性指标、微服务拆分、大规模 UI 美化。它们不能替代来源完整性、作用域和独立评估。

生产化之前要实证检验三个假设：中间层能否降低错题形式化，完整依赖检查能否减少错误复用，知识快照能否降低同标准核查的重复成本。如果不成立，改进或替换实现选择，同时保留 Charter 要求。

## 14. 下一次开始实施时的首批任务

1. 完成 P0.1—P0.5：固定标准、角色与评估集合。
2. 实现 P1.1、P1.2、P1.3：精确引用、六轴及范围处置，不先铺开全部存储与服务。
3. 用 P1.4 描述一个带未证依赖和异议的论证快照，验证不会错误升级。
4. 做 P2 的最小来源/主张路径，再接 P3.1—P3.2 的固定版本完整导入。
5. 通过身份、scope、引用依赖和归档义务的反向验收后，再连接自动 Prover/Verifier 循环及 Lean。

这些是可直接领取的实施入口。本次文档任务不勾选它们，也不启动 demo 来替代设计评审。
