# AgtXIv 可发布版本：实施与验收计划

**日期：2026-09-08。状态：私有网页首次发布及真实新论文处理已完成；全仓正式发布门槛与 V3 科学、治理工作分别记账。**

当前入口：[AgtXIv research website](https://agtxiv-research.dd2528575364.chatgpt.site)，采用 Sites 私有访问。以下 W1–W7 保留最初的实施与验收要求，末节记录实际交付。简明复核见[项目发布复核](../audits/project-release-review.md)。网页上线不表示匿名公开访问、Charter 已采用或全部科学义务完成。

本轮目标是检查整个项目，特别是全部 schema；补齐可发布版本所需的接口、真实数据路径、白色简约交互网页和可编译的 TeX 技术报告；整理项目目录并保全历史材料。网站、机器可读数据与技术报告应解释同一套对象和证据，读者能够追到原文、看懂论证与条件，并知道还有哪些工作没有完成。

可以把系统理解为带有实验记录的科学资料库：论文是原件，主张是可逐条查阅的卡片，论证图解释卡片之间怎样相互依赖，核查记录说明哪些检查真正做过。网页是阅读入口；接口是其他程序使用这些卡片的方式；技术报告是组织和维护这些内容的规则。它们必须指向同一份有版本的记录。

## 1. 范围与依据

本计划承接 [V3 58 项实施清单](v3-implementation-plan.md) 和[逐项执行状态](v3-execution-status.md)，不改写其完成标准。一次软件或网页发布不会自动完成 V3 的科学核查、正式认证或知识准入。V1/V2 科学材料保留原版本和原有证据；V3 仍按实际实施状态展示。Charter 的采用状态由既有治理文件记录，不能由本报告或网页的文字代替。

当前可用基础包括 V3 记录契约、本地来源检查、论证候选、六轴证据投影、候选保存与历史查询，以及 V1 的科学主张和形式化试点。最近一轮 [V3 候选证据](../evidence/v3-real-candidate/README.md) 记录 710 项测试通过，但其九项科学义务仍全部开放；这只是历史检查点，最终发布须重新绑定实际发布输入与验证结果。

参考网站 [physlib.io](https://physlib.io/) 用于讨论科学对象的浏览与展示体验。借鉴清晰的知识入口和图形探索方式；AgtXIv 的字段、科学状态和处理能力以本项目实际证据为准。

**已确定的产品范围：** 首发必须允许用户提交新的 arXiv 论文并真正启动分析。正式验收路径为“输入新 arXiv → 实际获取指定版本 → 创建并执行处理任务 → 显示进度或明确失败 → 返回结果与对应证据”。精选论文浏览保留为辅助入口，不能代替这条新增论文路径。支持的输入形式、材料类型、资源边界和分析深度须写进接口及页面；真实完成有限分析也不能冒充科学验证完成。

**硬截止：2026-09-08 03:00 Europe/Amsterdam（UTC+02:00），即 2026-09-08 01:00 UTC。** 到时停止开发和长任务，按实际结果总结已交付、已验证、失败与未完成项。未完成目标不得因到时而记作完成；必须保存可继续执行的待办、当前修改和必要日志。截止前不启动预计无法在截止前安全结束的新耗时任务。

## 2. 七项交付工作

### W1 — 全仓清点与发布边界

**输入：** 当前工作区、Git 状态、README、设计与治理文件、所有 schema 目录、代码、测试、数据、报告、演示和发布脚本。

**产物：** 全仓资产分类；规范与消费者关系图；发布问题清单；各版本入口和状态表；本计划及对应验收记录。问题记录应包含路径、实际行为、影响、修复办法及如何确认修复。

**执行细节：**

1. 记录已有修改和未跟踪文件，不将其当作废弃材料或覆盖为基线。
2. 区分当前实现、历史科学证据、研究提案、可重建产物和仅本地保留材料。
3. 追踪 schema 的生产者、校验器、数据实例、网页与文档消费者；不只检查名为 `schema` 的一个目录。
4. 对比设计、代码和发布入口，列明存在格式而无生产服务、存在测试而无真实输入、存在网页而未进入构建的部分。
5. 将必须在发布前修复的问题与后续研究问题分别标明适用的发布承诺，保留全部原任务。

**依赖：** 无。**负责角色：** 总体维护者、独立审计者、reader。

**验收：** 每个活动目录有用途和入口；每个发布阻塞有证据与处置；版本关系不靠“最新”一词猜测；独立读者能够解释本版输入、输出、可用能力和未完成部分。

**V3 对应：** P0.1–P0.5、P8.2、P8.5、P8.6。

### W2 — 全部 schema 与接口核对

**输入：** W1 清单；V1/V2 schemas、V3 `schema v0.0`、数据库与研究案例 schema；对应规范、生成器、校验器、实例和测试。

**产物：** 按文件登记的 schema 审计；字段语义与状态迁移说明；已实现读取接口的版本化契约；可运行示例和典型错误示例；生成一致性与跨记录验证结果。

**执行细节：**

1. 对每份 schema 检查版本标识、引用解析、必填/可空字段、枚举、未知字段、组合分支、长度与资源边界。
2. 核对记录身份、修订、内容哈希与原始字节哈希；跨文件引用必须绑定精确版本，不能混用路径、显示名称和对象身份。
3. 检查字段及条件能否准确表达共同前提、适用范围、未运行、未知、失败、冲突和候选状态，避免统一的“已验证”覆盖六种不同判断。
4. 用真实样本与最小合法/非法对照检查校验器；错误样本不得仅因格式错误被拒绝，而应触发它要检验的语义边界。
5. 对网页和其他程序实际使用的读取接口定义请求/响应、可用过滤项、排序、分页或明确的完整静态快照方式、空结果、错误、版本识别与快照身份。
6. 静态 JSON、命令行接口与网络 API 分别声明；为新的 arXiv 提交、任务创建、进度、失败与结果查询实现实际 HTTP 路由和 OpenAPI，并写清访问与资源约束。仅为已经可调用的能力提供使用示例，不把文档中的拟议端点写成在线服务。
7. 通过受控适配读取历史格式；不重新解释已冻结记录，不覆盖已发布标识对应的原 schema 字节。

**依赖：** W1；接口与报告可边审计边对齐。**负责角色：** 契约实现者、独立代码审阅者。

**验收：** 清单中每个 schema 均有检查结果或具体未解项；生成漂移、引用和正反例检查通过；网页实际消费的接口有可执行样例；不兼容变更有新版本或明确迁移说明。

**V3 对应：** P1.1–P1.6、P3.1–P3.2、P4.1、P4.8、P5.1–P5.5、P6.1、P7.4、P7.6、P8.1–P8.2。

### W3 — 真实案例与端到端数据路径

**输入：** 已固定论文材料、候选记录、历史 pilot、W2 接口、现有本地存储和投影实现。

**产物：** 从精确输入到网页数据的可重建案例；来源与状态映射；下载/读取示例；操作记录；成功、缺失证据和条件不匹配的可解释案例。

**执行细节：**

1. 优先将已有真实候选与历史 pilot 接入同一浏览入口，明确各自版本、材料性质和证据边界。
2. 将原文锚点、主张、联合推理、局部假设、依赖、评估、开放问题连起来。未获支持的关系仍作为候选，不升级为科学结论。
3. 保留原始论文和系统重构的区别，逐条展示限定条件与尚未覆盖的原文含义。
4. 使用现有历史读取能力固定展示快照；从新目录恢复后验证读取结果和记录身份不变。
5. 检查已提供关系中的依赖影响和冲突展示，明确输入之外的完整性未建立。
6. 对真正的科学复用、贡献或形式检查，只有取得对应真实证据后才展示完成；结构演示用例明确标为合成数据。
7. 实现首发必需的新论文处理：规范化新 arXiv 输入、解析精确版本、真实取得来源、创建任务、执行有限分析、保存运行和来源证据、返回结果。任务状态应区分排队、获取、处理、完成及失败，并提供可解释的错误与重试办法；不能用定时器动画代替实际状态。
8. 执行资源和输入限制必须在服务端落实；论文来源作为数据处理，不执行不受信任的 TeX 或附带脚本。保留失败尝试和缺失材料，防止一次异常丢失任务记录。

**依赖：** W2 的身份与投影接口；需要读取的历史原件先由 W6 保全。**负责角色：** 数据路径实现者、来源审阅者、领域审阅者。

**验收：** 至少一篇不在预计算演示列表中的新 arXiv 论文，经页面提交后实际取得来源、执行分析并返回结果和来源/运行证据；任务进度来自服务端实际状态。另检查非法输入、取源失败或处理失败，用户可看懂原因。真实路径可按说明复现；页面中的支持状态可回到精确证据；开放义务与缺失材料可见。科学阶段仍按原 V3 各项标准验收。

**V3 对应：** P2.1–P2.6、P3.2–P3.8、P4.1–P4.8、P5.1–P5.6、P6.1–P6.7、P7.1–P7.4、P8.1、P8.3–P8.4。

### W4 — 白色简约的可发布网页

**输入：** 已有三个视觉原型、W2 实际读取契约、W3 真实数据、技术报告与 schema 说明。

**产物：** 一个主要网站入口；论文与主张浏览页；交互论证图；源文/证据详情；schema 与报告入口；可分享链接及构建产物。

**执行细节：**

1. 采用白色背景、清晰文字、克制色彩和足够留白；状态不只靠颜色传达。
2. 让读者先理解项目解决什么问题，再进入真实案例。架构图用于解释工作流程，论证图用于解释特定主张的依据，两者应有明确标题和对象。
3. 点击主张查看原文定位、条件、依赖与六轴证据；允许聚焦上下游、查看联合前提和开放问题，并能返回完整上下文。
4. 统一标签和单位，提供必要的中文解释及术语表；不要求读者先学习内部缩写才能完成浏览。
5. 保证键盘操作、焦点状态、移动端布局、减少动画偏好、长公式和空数据/错误状态可用。
6. 新 arXiv 提交连接实际后台处理，显示真实执行状态、失败原因及结果链接；固定样例另设浏览入口。刷新后仍能根据任务标识查看进度和结果。
7. 将最终网站纳入实际 Pages 或选定托管构建，验证本地、子路径部署、刷新与深链接。旧演示保留明确历史入口或路径映射。

**依赖：** W2/W3 的可用数据；布局可先并行开发。**负责角色：** 网页实现者、reader、浏览器验收者。

**验收：** 不熟悉仓库的读者能提交新论文、观察真实任务、进入结果、定位原文、辨认未检查项并分享链接；页面无损坏资源、控制台错误或误导性完成状态；桌面与窄屏经实际浏览器检查；发布构建包含这个主要入口和可访问的处理服务配置。

**V3 对应：** P4.8、P5.5、P7.2–P7.6、P8.2、P8.6。

### W5 — TeX 守则与技术报告

**输入：** 已有 `draft/`、ScientificClaim 接口研究、贡献研究、W1 审计、W2 契约、W3 实例及 W4 读者路径。

**产物：** 一个明确的 TeX 主文件及章节、引用、图表、字段附录；可重复构建命令；PDF；规则—实现—检查—展示对应表。

**执行细节：**

1. 先解释动机和直觉，再给出对象、关系、流程、六维判断、版本规则及失败处理。
2. 对接口写清生产者、消费者、输入、输出、前置条件、不可变项、错误条件和兼容性；用真实小例子解释字段存在的原因。
3. 将来源、论证、形式证明和物理适用性的关系画清楚，说明条件定理和特定科学用途之间还需哪些证据。
4. 以同一字段来源生成必要附录，避免 Markdown、TeX 与 schema 手工复制后漂移。
5. 按章节标明已实现机制、当前发布行为和待研究方案；记录实际结果与局限，不把规范要求写成已完成实验。
6. 沿用有用文献和案例；新增相关文献按用户偏好优先使用 arXiv，并保留可追溯来源。
7. 编译并逐页检查公式、跨页表格、图例、引用和链接。正文应能独立阅读，而不只是 schema 文件列表。

**依赖：** W1/W2；实例和界面可随 W3/W4 同步。**负责角色：** 技术作者、契约审阅者、reader。

**验收：** 干净构建得到 PDF；无未定义引用或缺失图；关键规则均有适用版本、实现/证据对应；reader 能解释主要概念及其物理图像；文件标题“守则”不改变 Charter 的正式采用状态。

**V3 对应：** P0.1–P0.5、P1.1–P1.6、P4.4–P4.8、P5.1–P5.6、P8.2、P8.6。

### W6 — 目录整理与证据保全

**输入：** W1 清单、已有修改、文件引用、历史 hash 清单、`tmp/` 中唯一保留的完整数据库及字节、演示和报告产物。

**产物：** [整理审计](../audits/repository-organization.md)、[原路径到归档路径清单](../audits/repository-archive-manifest.json)、稳定本地证据副本、更新的[归档入口](../archive/README.md)。

**执行细节：**

1. 先备份唯一历史材料，再处理临时目录；归档记录包含原路径、新路径、字节数、SHA-256 和理由。
2. 明确移动与复制。不可重建的候选库及原始字节先复制保全，保留原件；重复的展示成品可移动到历史演示目录。
3. 修复普通链接；固定历史文件保留原文，由新路径映射解释去向。不能只更新 hash 字段掩盖输入变化。
4. 活跃科学材料不因版本旧就归档；本轮保留 `Reference` 固定输入、科学注册表、全部 `formal/.lake` 缓存以及仍在修改的演示稿。
5. 公开网站构建采用明确文件清单，本地保全不等于允许公开分发。
6. 为归档写恢复命令和校验方式，注明同机副本尚不构成异地备份。

**依赖：** W1 的引用检查；证据保全先于其他清理。**负责角色：** 仓库维护者。

**验收：** 原始文件内容可按哈希核验并恢复；单独追加的迁移说明有原始长度和独立哈希；本地历史副本与旧回执全部匹配且原件仍在；普通活动入口有效；固定历史证据未被改写；没有丢失用户未提交工作。

**已执行范围：** 五个完整候选历史文件复制保全并保留原件；四个根目录展示成品移入 `docs/archive/presentations/2026-08/`；两个旧原型的 17 个文件移入 `docs/archive/prototypes/`。清单共 26 项、18,943,027 目标字节；三份 README 只追加迁移说明，原内容可恢复。仍有测试和导出消费者的 `demo_design/`、Pages 及活跃科学材料保留用途明确的原路径，具体依据见[组织审计](../audits/repository-organization.md)。

**V3 对应：** P6.4、P7.3、P8.1–P8.2；本地副本不完成生产不可变归档 P6.4。

### W7 — 集成检查与发布交付

**输入：** W1–W6 产物、锁定环境、现有 CI、Pages 构建、版本与发布政策。

**产物：** 发布候选检查记录、固定输入/产物清单、更新的发布说明、站点构建、TeX/PDF、接口使用示例和所有剩余限制。

**执行细节：**

1. 将 V3 schema 生成、协议生成、bundle 校验和实际消费路径纳入适用检查，不只依赖旧版验证入口。
2. 运行全仓适用检查并区分通过、实际失败、已知阻塞和未运行；受限的形式化构建按现有真实边界记账。
3. 从干净检出和锁定依赖重建网站及报告；核对生成漂移、公开文件范围、下载内容及链接。
4. 以真实读者任务验收浏览器页面，并独立复核机器接口与网页对同一条记录给出一致状态。
5. 固定发布候选输入及输出身份，记录版本、兼容性和已知问题。交付同时包含网页与新论文处理服务的运行/部署说明；仅静态 Pages 无法承担处理服务时必须明确服务部署位置与连接配置。若执行公开部署，则核对实际访问地址；本地运行不得记作已上线。
