## 2. 三种处理标准：必须做的工作与必须成功的工作

`processing_standard` 使用主规范中的完整名称。路线图里的 `SOURCE_MAP`、`ARGUMENT_AUDIT`、`FORMAL_SUPPORT` 是简称。

一个义务有两个不同问题：**有没有完整交代处置**，以及**要求成功时是否真的成功**。例如，“尝试证明失败并列出缺口”可以完成调查记账，却不能满足该目标的形式支持义务。

| 标准 | 必须完成并交付的工作 | 必须成功的义务 | 允许保留的缺口 |
|---|---|---|---|
| `V3_SOURCE_MAP` | 精确来源资产；正文、附录、图表和引用结构清点；来源主张与条件；未分类项；独立范围审阅；全部六轴的适用性和处置；基准、候选贡献及前沿记录 | 所冻结范围内来源引用可解、字节匹配；来源条件无已知未处置遗漏；独立冻结决定满足身份规则；每个发现项都有归属或明确未分类处置 | 数学、形式、语义、经验和计算可以未执行；无法识别的来源范围不得伪称完整。来源缺失仍可归档候选调查，但不能宣称对应精确来源义务成功 |
| `V3_ARGUMENT_AUDIT` | 以上内容；承重数学步骤、共同前提、局部假设、跨论文依赖、证明方案；独立异议处置；科学语义映射；各节点未解项 | 要求审阅的每个承重项有独立审阅处置；依赖和局部假设不被隐藏；语义检查已执行并记录适用范围 | 数学结果可以有条件、存在反对证据或不确定；未证外部依赖、未形式化节点和经验/计算缺口保留。发现错误不使调查包失去保存资格，但不授予该结论正面支持 |
| `V3_FORMAL_SUPPORT` | 以上内容；冻结形式目标清单；精确交接；独立声明检查、公理检查、反向解释和三种对齐；目标级证据与剩余边界 | 每个 `MUST_SUCCEED` 形式目标都必须实际获得所选政策允许的声明证据和独立对齐；没有 `sorry`、目标公理化、未许可公理或未参与构建的目标；任何必要输入缺失均不得满足该目标 | 冻结形式集合之外的主张可有缺口；语义与经验缺口仍保留且限制可用科学结论。一个形式目标失败即可保留调查包，但不可宣称满足本标准 |

对各标准共同要求：

- 六轴必须全部出现；不要求每个轴正面成功。`NOT_APPLICABLE` 是有范围和理由的判断，不是“没做”的替代词。
- 每个固定义务绑定目标、证据方法、成功要求和当前处置；历史尝试保留。`MUST_ACCOUNT` 要求可审计处置，`MUST_SUCCEED` 还要求成功证据。此处词语表达政策语义，具体字段以实验契约为准。
- 原文条件提取遗漏是提取修订；为了证明新增条件是另一命题；新发现承重项是范围扩展。三者均不可覆盖旧记录。
- 所有清单变更产生新修订并说明理由，旧分母仍可计算。不能在失败后删目标来取得原标准的成功。
- 贡献记录始终存在：证据不足时为“相对此基准待判断”，不能省略，也不能写成零贡献。

经验与计算证据采用正交附加要求，而不是创建大量组合标准。`evidence_requirements` 在冻结前逐目标指定轴、材料、范围、方法、比较规则、允许处置与成功条件。若某经验结论必须获得支持，缺失数据不能满足；若只要求审查现有证据，发现数据缺失可以是合格的审查处置。随机计算在运行前固定随机机制、容差或统计比较规则；复现成功不会自动支持模型或经验结论。

## 3. 角色、实际身份与可见输入

直觉上，生产者负责写出“待检查的账本”，审阅者负责核对账本与证据，认证者只核对手续和精确绑定。给同一进程换三张名牌，并没有多出三次独立检查。

### 3.1 身份证据层次

下列层次是本实验的证据描述，不是新授予的生产资格。实际编码可使用等价的有版本枚举。

| 层次 | 证据 | 可用于什么 | 不能推出什么 |
|---|---|---|---|
| `DECLARED_ONLY` | 调用者填写的名字、角色、`author` 或 `validated_by` | 保存归属声明、候选材料和原始事件 | 不能证明身份独立或科学资格 |
| `EXECUTION_ATTESTED` | 工作区之外的受控调度回执，绑定实际账户/进程、运行、角色、模型、可见输入和精确输出 | 本地受限实验的独立性检查；允许的 agent 审阅证据 | 调度者仍可能有控制权；同模型错误不独立；不等于实名、资质或密码学签名 |
| `GOVERNANCE_AUTHORIZED` | 采用的角色政策、实际主体与授权范围、资格/利益冲突、有效期和可检查凭证 | 在已采用政策明确允许的范围内作正式决定 | 技术权限不等于科学资格；资格不能跨领域或越过授权期限 |

所有关系至少检查 `actor_id` 对应的实际主体和生产参与者集合，不能只比较 role/name。缺少映射时保留 `DECLARED_ONLY`，不能自动向上升级。一个模型的多个独立运行可以提供有用交叉检查，但记录其相关性限制；它们不能替代尚未满足的人类资格要求。

### 3.2 每一精确候选的分工矩阵

| 角色 | 可见输入与输出 | 必须独立于 | 权限边界 |
|---|---|---|---|
| Coordinator 调度者 | 计划、预算、依赖和运行回执；安排工作 | 论文审计者、机械认证者 | 不授予科学状态，不批准自己组装的包 |
| Producer 来源/主张/论证生产者 | 精确来源和必要背景；输出候选、公开论证和归属 | 对该产物作独立检查的所有审阅者 | 可回应异议，不能自行关闭对自身产物的独立异议 |
| Scope Reviewer 范围审阅者 | 全文来源结构、发现清单、处理标准和遗漏项 | 发现生产者及政策规定的其他冲突主体 | 冻结具体分母，不确认论文全部正确 |
| Argument Reviewer 论证审阅者 | 完整节点、共同前提、依赖、异议、局部范围及公开证据 | 节点作者及所有证明贡献者，包括不同的 `proof_author` | 记录审阅与异议处置；不替代 Lean 或科学适用性评估 |
| Formal Producer 形式化生产者 | 固定交接、允许依赖和环境 | 独立检查者、反向解释者、形式对齐审阅者 | 可寻找或编写证明，不批准自身输出 |
| Formal Checker 形式检查者 | 固定环境、完整输入、目标清单、公理政策 | 形式化生产者 | 产生声明检查证据，不判断原文含义 |
| Back Translator 反向解释者 | 形式声明、实际定义和必要环境 | 形式化生产者 | 第一轮不看源论文、预期自然语言目标和先前对齐结论；输出后冻结，再交给对齐者 |
| Alignment Reviewer 对齐审阅者 | 原文、论证/交接、Lean 声明、已冻结反向解释 | 被审对象的全部生产者、反向解释者 | 分别检查源→交接、交接→形式、源→形式；不得复制前两项冒充第三项独立检查 |
| Scientific Assessor 科学评估者 | 对象映射、单位/近似、经验及计算证据、正反评估 | 自己正在评估的证据生产者 | 按独立轴判断具体用途；领域资格不足时只能给候选意见 |
| Paper Auditor 论文审计者 | 精确候选清单及范围、全部相关评估、贡献和前沿 | 该候选生产者、Coordinator、Certifier、Admission Reviewer | 检查是否满足所选处理标准；不生产自己审计的证据 |
| Certifier 机械认证者 | 固定清单、审计、身份回执、契约和政策 | 该候选生产者、Coordinator、Paper Auditor、Admission Reviewer | 核对机械门槛，不改变科学判断或前沿 |
| Admission Reviewer 知识准入审阅者 | 逐条候选、科学证据、拟用途、冲突和目标快照 | 该候选生产者、Paper Auditor、Certifier | 只有正式采用的准入政策允许时才作正式准入；归档不代替准入 |
| Reader 可读性审阅者 | 面向人的输出及能定位的结构化证据 | 原说明的生产者 | 检查缩写、直觉、物理图像与边界；不授予科学认可 |

矩阵描述本实验设计，实际生产约束不得弱于 `GOVERNANCE.md` 和已采用的具体分工政策。科学评估者和准入审阅者的资格、人数、回避与申诉规则尚待正式采用；本文件未冒充该采用行为。审阅期间改动被审字节，须输出新候选和新审阅；不能边改边批准同一身份。

### 3.3 agent 可以推进什么，何时需要人类

三个标准的普通候选生产、机械验证和有标记的 agent 交叉审阅都可继续。不存在“选择形式标准便一律需要人工点击”的隐含规则；也不存在“全是 agent 的意见自动足够正式准入”的默认规则。

来源中的物理模型、测量约定、近似或经验结论出现歧义或相互矛盾时，先保留明确 `FrontierItem` 和受影响的用途边界，再交给具有相应资格、证据访问权限且满足独立性要求的审阅者继续。审阅者可以是现行政策允许的 agent 或人类；普通科学歧义本身不产生人工批准门。缺少来源或数据时，也应先执行已授权的查找、取得和核对工作，保留未找到的材料，不自行补造。

只有具体决定受到以下现行要求约束时，才需要相应的人类或权利主体介入：

1. `GOVERNANCE.md`、Charter 的已有批准程序或明确采用的角色政策，要求维护者、合格领域人员或指定主体批准、任命或作出正式决定。
2. 某次正式科学准入、公开发布或签名决定所必需的资格、独立身份、利益冲突处置或授权尚未具备，且解决它需要上述治理程序。受阻的是该正式决定；候选反例、贡献分析、独立证据审阅和工程实现仍可继续。
3. 权利许可或授权范围只能由权利人及其获授权代表决定，或确需作者、数据持有人提供尚不存在于可取得材料中的事实。仅在缺少这些决定或事实的相关部分等待；已有授权范围内的工作继续。

每次需要人类介入都须指出适用的已有规则、精确政策版本或所缺的权利人决定，不能从本基线推导新的普通本地实施审批门。当前可以自主实现和检验这些边界，但不得伪造任命、签名、权利许可或科学认可。

## 4. 固定评估输入：材料分母与核查分母分开

英文机器清单位于 [`evaluation-corpus.json`](../../schema%20v0.0/evaluation-corpus.json)。它固定当前本地材料的相对路径、字节长度和 SHA-256，以及从旧记录读取的状态、记录定位和未复核字段。路径用于找到材料，字节哈希用于确定读的是哪份材料；目录不充当科学身份。

核心领域选为稳定子与 magic 资源。magic 在这里指稳定子运算之外的量子资源，不是日常意义的“魔法”。材料链包括：

| 位置 | 论文及旧记录身份 | 用于检查的接口 |
|---|---|---|
| 前置概念 | *Stabilizer Codes and Quantum Error Correction*，`arxiv:quant-ph/9705052v1` | 原文构造与现代量子比特/密度算符重构的归属；源条件遗漏 |
| 前置资源定义 | *The Resource Theory of Stabilizer Computation*，`arxiv:1307.7171v1` | 自由集合、相空间/维数范围和定义桥接 |
| 前置度量 | *Application of a Resource Theory for Magic States to Fault-Tolerant Quantum Computing*，`arxiv:1609.07488v2` | 源通道条件与更严格形式接口是否相同 |
| 直接依赖 | *Predicting Magic from Very Few Measurements*，`arxiv:2602.18939v1` | 固定窗口与共同旋转窗口；原文证明与修复证明；条件形式声明 |
| 后续目标 | *Graph Theoretic Approach to Quantum Nonstabilizerness*，`arxiv:2607.26154v1` | 外部依赖是否合格、局部数学与整篇结论、缺失计算材料和贡献基准 |

上述 arXiv 版本身份来自现有本地记录，本次没有重新访问 arXiv 核实下载链。清单固定了“当前读到的字节”，没有因此确认“这些字节就是出版版本的完整材料”。P2 仍须核实下载证据、include/宏、正文与附录、图表、活动与注释内容、主张全覆盖和独立冻结。

清单同时收录研究假定关系、V2 候选契约和旧研究中的贡献结果，作为迁移和错误升级的反向材料。这些附加材料不扩张核心五篇论文的科学验证分母。文件叫 `gold` 或标签写 `ASSUMED_VERIFIED_FOR_STUDY` 都不能让它成为本次科学标准答案。

### 4.1 三种数量不能混算

- **材料分母**可以现在固定：列出的文件数、五篇核心论文、历史记录行数、A01—A21 与 VF-01—VF-13 的案例清单。
- **核查分母**仍是 `null / NOT_FROZEN`：每篇全文主张数、承重步骤数、形式目标数、经验/计算义务数。旧 registry 行数只能帮助计划，不能代替独立全文发现。
- **成功分子**也是 `null / NOT_EVALUATED`：没有对该冻结分母执行 V3 核查，就不报告百分比，也不把未知写为零成功。

当前输入状态是 `INPUTS_PINNED_REVIEW_PENDING`。这是材料清单版本，不是 `ScopeFreezeDecision`、知识快照、科学批准或发布包。独立审阅者应核查选择是否偏向容易成功的结果，补齐缺失材料后以新版本冻结实际工作范围。

### 4.2 真实反向材料与尚需构造的情形

固定窗口反例记录的直觉是：固定视野看到的是物体的投影。转动物体可以把原本隐藏的分量转进视野，投影变大不等于资源增加。共同旋转物体和视野属于另一命题。清单只保存旧反例陈述和来源位置，尚未重新核对计算、来源语义或独立反驳范围。

原文凸包证明的缺口、独立修复路线和条件 Lean 声明可以用于检查“结论证据不替代作者方法”。但现有材料不能直接证明已有两条完全独立且合格的证明；A13/VF-12 仍需在固定依赖图上构造并检查两个方案。

图 2 的代码、原始样本、种子和抽样规则缺失，是计算证据不足的真实历史记录。本次不能把这些材料缺失推成实验结论错误。历史 `kernel_build=PASSED` 同样只是旧日志声称的事实；没有新环境、声明、公理、身份和对齐检查，就不升级为 V3 形式支持。

清单逐项关联 A01—A21 和 VF-01—VF-13。每项区分 `HISTORICAL_INPUT_AVAILABLE` 与 `ADDITIONAL_FIXTURE_REQUIRED`，并列出应观察的行为、必须补充的证据和当前 `NOT_EXECUTED` 状态。带真实材料不意味着已执行验收；缺少真实 vibefeld 事件时尤其不能补造一次曾发生过的审阅。
