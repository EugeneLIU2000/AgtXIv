## Verdict

How the one existing example was actually produced (the central question, answered from evidence): there was no executable runner. A model read Pauli_Spectrum.tex end to end in a single interactive session and wrote the entire extraction by hand into extraction/seed.json (440,887 bytes; its own extraction_note says so). host/assemble.py then replayed that seed into the five-round folder: it takes no model, makes no network call, and I proved it is a pure function of the seed by running it into a scratch directory, where in 18.2 seconds it reproduced records.json, claims.md, validation.json and every rounds/*/{task,draft,records}.json byte-identically. So rounds/*/draft.json is GENERATED BY THE SCRIPT, not captured from a model. The five "rounds" are five Python functions slicing one seed. host/verify.py is read-back only (I ran it: exit 0, 14/14 checks). The 1.0 sibling's README says the same thing in the repo's own words: the script does not call a model, and switching papers requires a fresh real reading that the script cannot do.



What that means for 2607.26154v1. Three things block any output at all: no seed (PA-01, ~16h, content work), no assembler for this paper (PA-02, ~6h), no acquisition.json (PA-03, ~1h). The seed does not - it is roughly two days on its own, it is reading-and-judgement work rather than engineering, and it cannot be parallelised with the assembler port because the assembler must be debugged against a real seed. With 7 days to 0923 this is achievable, but only if the seed authoring is scheduled now as its own task rather than treated as a by-product of the framework work.



Two honesty boundaries the user must settle before the run, not after. (1) The full RecordSet will be invalid with one SELF_REVIEW per claim-component-map - structurally, because review is required and the producer is its own reviewer (PA-06). check_output.py, which CONFORMANCE.md section 5 names as the Paper Agent's runnable checker, returns exit 0 on exactly such a record set; I confirmed this on the reference run's 433 records. If "passing the project's own offline checkers" means check_output.py, the goal is met; if it means RecordSet.validate, it is unreachable with one principal and no amount of build time changes that. (2) The delivery will be mode OFFLINE_DIAGNOSTIC with no result.json, because no host, scheduler or runtime identity exists (PA-07) - host_reference cannot even import, since neither pydantic nor pydantic_ai is installed. Calling that "end to end" is defensible only in the same sense the existing example is; a genuinely host-driven paper.extract is weeks away, not days.



Scope realism for the extraction itself: the target is 69,678 bytes against the reference's 207,034, with about 9 numbered assertion environments against 44, so expect roughly 25-35 ScientificClaims, 40-60 spans and 120-150 span-cited conditions.
