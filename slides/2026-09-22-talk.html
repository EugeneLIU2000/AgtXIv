Part 0 · GroundVocabulary

Four words, before anything else

None of these are deep. All four get used loosely in public, and the looseness is where the confusion in this field lives.

Agent
the actor
A language model in a loop: it is given a goal, allowed to call tools, and run until it stops.
Not a program you wrote. It decides what to do next.
MCP
the socket
A published convention for exposing a tool — a database, a compiler, a filesystem — so any model can call it.
Like SI units for instruments. It standardises the plug, not the measurement.
Schema
the form
A machine-checked description of what a valid record contains: which fields, which types, which are required.
The only one of the four that can refuse. This talk is about that.
Skill
the procedure
A written procedure the model loads when a task matches it — a lab protocol, not a capability.
Advice. It can be read and ignored, and nothing records that it was.
Three of the four are ways of asking. Only the schema is a way of refusing.

What the thing actually is, from outside the API

01

A stateless function. Nothing carries between calls. There is no memory, no session, no accumulated understanding — each call starts from nothing but its input.
02
It does not output text
It outputs a distribution over the next token. The text you read was sampled from that distribution. What the model produced is the distribution.
03
One frozen forward pass
Fixed weights, no write-back. The network does not learn from your call. Whatever happened, it did not change the thing that did it.

Part 0 · Ground
Part 0 · GroundSampling is the mechanism
The distribution, written in a notation this room already owns
P(tokeni) = eℓi/T Σj eℓj/T

A Boltzmann distribution over tokens. The logits ℓ play the role of negative energy, and T is the temperature. T → 0 is the ground state.

So “why did two calls answer differently?” is the wrong question. Sampling is not a defect to be engineered away — it is the mechanism. The right question is what the query left undetermined, because that is what the sampling ranges over.

Part I · The problemSix questions

Six different questions about one sentence

Source fidelityIs this what the paper says?
Mathematical correctnessDoes the conclusion follow from the stated assumptions?
Formal alignmentDoes the formal statement mean the paper’s statement?
Semantic applicabilityDoes the formal object represent the physical system?
Empirical supportWhat supports the modelled regime?
Computational reproducibilityCan the load-bearing numerics be regenerated?
Every one of them collapses into the single word “verified” — in a referee report, in a citation, and most of all in anything a language model says about the paper. They are not degrees of one thing. Different evidence, different checkers, and different people competent to sign them.

Part III · The ideaWhy the constraint cannot be an instruction

A prompt is a request.
An interface is a refusal.

If agents are going to extract, compare and formalize claims, the epistemic constraints cannot live in the instructions. An instruction is advice. A contract that cannot represent the dishonest answer is a different kind of object. Concretely: additionalProperties: false — a model cannot add a field nobody agreed to.

One concrete failure

Osborne’s agent probed the machine for quantum-chemistry software. which orca returned /usr/bin/orca — which is GNOME’s screen reader, not the ORCA quantum-chemistry package. A grep in the same sweep matched imagemagick’s “quantum depth”. Nothing was installed, and the name matched anyway.

What follows

A name match is not an identity match. Which is why a reference in this system is four parts — record type, record id, revision, content hash — and never a path or a display name.

Not because paths are inelegant. Because /usr/bin/orca resolved.

Part III · The idea
Part III · The ideaImpossible, not discouraged

Three things the contract makes impossible

  • A producer cannot review its own output. And — the sharp version, borrowed from Paper2Agent — changing a role prompt inside one agent context does not create a second reviewer.
  • A backtranslator cannot see the source. Not “should not”: its context does not contain it.
  • A fixed program has no scientific discretion. The thing that runs Lean cannot decide what the result means.

And a task can correctly deliver bad news

“Cannot prove this; lemma L is missing” is a correct delivery. So the outcome vocabulary has no SUCCESS:

DELIVERED  BLOCKED  FAILED  DEFERRED

COMMITTED means a candidate transaction completed. It is not a claim about truth. A marker that work ended is not a record that it passed.

Part V.6 · The roots, in LeanGottesman · arXiv:quant-ph/9705052v1

What it took to make one root machine-checked

-- the root's own sentence, as a Lean statement theorem finrank_commonFixed_eq_two_pow_sub (F : IndependentSignedPauliFrame n r) (h : r ≤ n) : finrank ℂ (commonFixedSpace F) = 2 ^ (n - r) -- and the k = 0 specialisation: a pure state theorem finrank_commonFixed_eq_one (F : IndependentSignedPauliFrame n n) : finrank ℂ (commonFixedSpace F) = 1 theorem normalized_fixed_vectors_differ_by_phase -- ... unique up to a global phase: a ray
Read it as a contract
You hand it an independent signed Pauli frame of rank r — the Lean form of “abelian Pauli subgroup not containing −I”, with the −I exclusion an actual field.
It owes you the dimension of the common +1 eigenspace, exactly 2n−r. At r = n that is 1 — and a one-dimensional fixed space, with the phase theorem, is a pure stabilizer state.
It never asks you to believe the character profile or the group order — both are derived, not hypotheses.

Roughly 24 of the 43 audited declarations stand behind those three lines: the Pauli trace formula, the −I-exclusion argument, the generator-wise ↔ group-wise eigenspace bridge, and all five projector properties — Hermitian, idempotent, positive semidefinite, trace, rank.

And the honest edge: no frame with r < n is ever constructed in the repo, so the general case is proved but never instantiated.
