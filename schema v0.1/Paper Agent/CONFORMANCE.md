# Paper Agent 1.1：同一题的判定规则与正反例

这是规范性附件。例子全部是人工教学材料，不是论文验证结果。目标不是让模型背同一个答案，而是对同一段原文采取同一种处理方式。

## 1. 发生冲突时的固定优先级

原文断言边界 → 量词与条件的作用范围 → 可独立使用的结论组件 → 默认数量与排序。不得为满足“一组件一目标”拆坏同一个存在对象、联合概率事件或等价关系。确实无法决定时，保留原文整体并说明歧义，不自由选择一个更方便的版本。

按原文阅读顺序列主张，按断言内出现顺序列组件。组件 ID 在同一主张内采用 `component:conclusion-1`、`component:assumption-1` 等角色加序号；条件 ID 采用 `condition:source-1` 等。局部编号可在不同主张中重复，必须连同主张引用使用。排序不用于改变数学量词顺序。

断言去重只采用 AGENT R2 的明确原文互指规则；跨章节的隐含等价、特殊情形或疑似重复交后续比较。不要用“所有模型恰好输出 N 条”当一致性目标。

## 2. modality 的固定判定顺序

先按不同来源强度拆开可独立断言，再从上到下选第一个符合者；复合命题不可拆时，用承载整个结论的断言强度，其他信息保留在组件、条件与缺口中。

| 优先级 | 值 | 什么时候选 | 不表示什么 |
|---|---|---|---|
| 1 | `CONJECTURED` | 原文把该结论称为猜想、推测或尚待证明 | 模型暂时不会证明 |
| 2 | `OBSERVED` | 该结论是有限实验、数值结果或图表观察 | 普遍数学定理 |
| 3 | `INTERPRETIVE` | 该结论本身是科学解释、类比或意义判断 | 所有涉及物理的命题 |
| 4 | `CONDITIONAL` | 作者显式以未证猜想、尚未成立的外部结论或条件性论据支撑整体结论 | 普通定理的定义域／适用假设 |
| 5 | `APPROXIMATE` | 结论本身是近似描述／近似模型下的估计，且不属于以上情形 | 模型不确定、或一个严格误差界定理 |
| 6 | `ASSERTED` | 普通明确断言，包括带适用假设的严格定理 | 系统已验证或独立认可 |

数学目标的 `exactness` 单独保存 EXACT／APPROXIMATE／ASYMPTOTIC；不要由 modality 机械复制。一个严格的渐近定理可为 ASSERTED + ASYMPTOTIC，一个数值观察也可能只支持近似关系。没有足够原文判断时保留实际语句与明确缺口，不宣称检查器能替你判定。

## 3. 最小正反例

### E01：一个原文命题，两个独立数学结论

原文：“本节 n、k 为正整数，a_i∈[0,1]，定义 A_k=Σᵢ₌₁ⁿ a_i^(2k)。命题 1：A_(k+1)≤A_k，且 A_k≥0。第一式由引理 L 得到。”

- 应有一个 ScientificClaim，对应命题 1；其中两个 CONCLUSION 组件。
- 应有两个 MathClaim，各保留完整的 n、k、a_i 条件，使用同一 A_k 定义。一个定义不是第三个结果。
- 第一目标的证明位置及引理 L 是交接线索，不把“引理 L 成立”塞进该目标 assumptions。
- 章节范围在本命题附近未重写，提取时以 SOURCE_RECONSTRUCTED 引用章节约定；局部明确写出的前提以 SOURCE_EXPLICIT 引用局部句子。两者均有直接来源定位。
- 禁止：两目标共享一段不可追踪的条件字符串；或仅提取比较容易的第二个目标。

直觉：0 到 1 的数乘以自身平方不会增大。但即使这一步容易想到，也不是原文已经写出的证明。Paper 可以说明直觉，不把新增推理当原文内容。

可运行草稿 [claim-draft.json](conformance/claim-draft.json) 仅展示第一轮的 ScientificClaim；其中所有引用明确为 synthetic fixture，不可用于真实任务。后续数学目标必须等它被真实宿主登记并通过新 Task 提供引用后再生成。

### E02：共享存在对象不可拆

原文：“存在同一个态 ψ，使 P(ψ) 且 Q(ψ)。”

- 一个联合 CONCLUSION、一个 MathClaim，保留存在量词作用于整个合取。
- 禁止：拆成“存在 ψ₁ 满足 P”与“存在 ψ₂ 满足 Q”，它们不保证同一个态。
- 同理，“以至少 1−δ 的概率同时满足 A 与 B”不能拆成两个各有概率保证的目标；A↔B 默认保留等价整体。若未来 Proof 分析两个方向，那是证明工作，不是改写原文目标。

### E03：条件缺失，不主动修复

原文定义 W(β)=log Z(β)/β，但没有交代 β=0，同时宣称“对所有 β”。

- ScientificClaim 保留“所有 β”；用来源定位标出定义与断言之间的问题。
- 若无法给出无歧义的数学对象／定义域，保留该组件但暂不生成 MathClaim，报告缺失项；建议“检查 β≠0 版本或极限延拓”放后续请求。
- 禁止：偷偷把 β≠0 写入原主张，或声称 W(0)=0 作为原文事实。不得把模型建议的延拓标为 SOURCE_RECONSTRUCTED。

### E04：还原条件有边界

原文明确说“本节均为纯态”，定理只写“任意 ψ”。

- 可还原 ψ 为纯态，并引用该章节约定；在 normalization 说明记号还原。
- 如果相邻另一段明确讨论混态，须先确定约定是否仍适用，不能因为纯态目标更容易就选纯态。
- 展开显式定义、继承明确范围和替换记号可以是还原；新增引理、推导新界、修正疑似笔误不是还原。

### E05：量词顺序不是排版选择

原文：“对每个 ε>0，存在 N，使对所有 n≥N 有 |x_n−L|<ε。”

- quantifiers 按 ∀ε、∃N、∀n 的顺序，保留范围与依赖关系。
- 禁止：按变量字母排序成 ∃N、∀ε；不得把依赖 ε 的 N 当作统一常数。
- “2+2=4”是闭命题，可用空量词数组；不为了非空而造一个 n。

### E06：定义与科学解释各有用途

目标只使用 A、B 两个定义；论文还有 C、D。

- 仅引用 A、B；对象列表从实际目标提取，不复制所有定义中的对象。
- 若数学对象就是论文中的纯数学对象，且没有额外解释残余，semantic_refs 可为空。
- 若论文把一个数学函数解释成某种物理功或可观测量，该解释及适用模型单独保留；不能因暂时不能形式化就丢掉它。

### E07：观察与定理不能互相替代

原文：“图 2 中测试的 20 个样本均满足 f≤1，猜想所有态均满足该界。”

- 样本观察为 OBSERVED，普遍猜想为 CONJECTURED，分别保留来源与范围。
- 禁止：合成一个 ASSERTED 的“对所有态 f≤1”；也不能因猜想尚未证明就不保留它的数学目标。

### E08：未读与不存在不同

附录文件丢失，正文说“证明见附录 B”。

- 保留正文主张及可提取数学目标；报告缺失附录与证明位置线索。
- 不得写“论文没有证明”，不得把缺失文件从计划清单删掉。该缺口阻塞哪些任务由其前置条件决定，不自动停止所有候选提取。

### E09：原文重复与不同版本

引言明确说“下面的定理 2 给出该界”，条件与定理一致。

- 把引言位置作为定理主张的额外来源。
- 另一编号命题、不同范围、不同版本或仅看起来等价的断言不自动合并。需要比较时保留两边原文位置，交后续比较。

### E10：候选对应不是独立审阅

Paper 生成 claim 到 math 的对应，当前没有独立 reviewer。

- 如实保留 UNESTABLISHED 和真实参与者；草稿结构可通过，但 v0.0 完整记录集仍可能 SELF_REVIEW 失败。
- 禁止：新造一个 principal 名字、删 map、或仅展示去掉 map 的子集通过来宣称原任务成功。

## 4. 一致性如何验收

先做机械检查，再做来源对齐审阅，两类报告分开：

1. **机械不变项**：固定草稿字段、合法业务 payload、预声明输出类型、引用在当前 Task 中、来源条件有直接定位、装配不改变 payload、真实执行前置条件。checker 只覆盖其报告明确标明的项目。
2. **内容覆盖**：按原文断言位置配对，逐项比较结论组件、对象与量词、适用条件、强度、数学化或未数学化的理由。范围内未配对项必须列出，不被相似度平均掉。
3. **差异处置**：措辞不同但原意相同可接受；缺条件、量词不同、无依据修复或遗漏必须报告。多个模型一致也可能一起错，最终对照原文，不以多数票代替证据。

命题个数、token 数或 JSON 文本相似度不能单独作为质量指标。准备人工核对的小型基准时，记录原文位置与必须保留的语义项，而不是强迫某个模型答案成为完整真值。

## 5. 现在可运行什么

从仓库根目录运行：

```bash
.venv/bin/python -B 'schema v0.1/Paper Agent/check_output.py' --draft 'schema v0.1/Paper Agent/conformance/claim-draft.json'
.venv/bin/python -B 'schema v0.1/Paper Agent/check_output.py' --records 'schema v0.1/Paper Agent/example/2608.14798v1-claude-opus-5/output/records.json'
.venv/bin/python -B -m unittest discover -s 'schema v0.1/Paper Agent/tests' -v
```

真实 Task 可用 `--draft <draft.json> --task <task.json>` 增加当次输出类型、记录引用和附件引用检查。未提供 Task 时，相关检查明确为未执行；不是默认通过。`--records` 对旧案例检查单条业务记录及基础填写规则，不执行完整 RecordSet、源字节验证或科学检查。源假设缺直接定位的历史案例会失败，这是发现问题，不是测试工具故障。

退出码 0 仅表示已执行机械检查未发现问题；1 表示检查发现问题；2 表示输入／工具使用错误。这些测试是人工契约正反例，**不是已经重新运行两个模型、证明一致性提高的实验**。

2026-09-13 检查结果见 [validation-report.json](validation-report.json)：本目录新增 25 项测试与原编排层 28 项测试通过；两份旧例单条记录结构及哈希均通过，Claude 目录旧例另被基础填写检查指出 67 处条件来源缺失与 3 处缺结论组件。上一份未被这些有限规则报错，不表示其拆分、主张强度或数学目标覆盖已合格。
