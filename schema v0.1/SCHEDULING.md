# 调度规范：围绕 claim 的缺口派单

本文件规定目标行为。`validate.py` 只检查离线工作单和回执，不是运行中的调度器。

## 1. 直觉与三个不同的图

新论文的结论 C 依赖旧引理 L。系统先向历史查找 L，再从可用的 L 向 C 推进证明。查找方向和验证顺序不必相同。

- **证明图**：某一条固定证明路线内，前提到结论的依赖不能循环。A 与 B 共同推出 C，需要一个完整的推理步骤；两个前提不是各自独立的证明。
- **知识关系图**：还包含引用、等价、修正、争议和多条证明路线；不要求整个数据库是一张无环图。
- **工作图**：每一版工作单之间的先决关系无环。研究过程可以反复修改，但每次产生新任务或新尝试，不回写过去的工作图制造循环。

任务调度的单位是“对精确版本目标做一次有界工作”，不是“让一篇论文的 agent 永久运行”。

## 2. 谁负责调度

| 部分 | 负责 | 不负责 |
|---|---|---|
| Planner | 根据目标和开放缺口提出任务、优先级建议 | 自己启动无限子 agent、授予写权限、认可科学结果 |
| Scheduler（固定程序） | 验证工作单、检查依赖门、分配执行者、预算、租约、重试和保存回执 | 用“模型觉得没问题”替代所需证据 |
| 专业 agent | 在允许的输入和工具范围内产出业务候选、公开论证和后续请求 | 绕过队列直接改其他 agent 的结果或数据库 |
| Utility / 检查服务 | 执行固定工具、验证、持久化、导出和建立投影 | 自行改变字段含义或科学状态 |

共用代码不等于共用权限。形式检查、机械认证及正式审阅的执行归属仍按旧角色政策分离。调度器必须记录真实可见输入，不能直接相信模型填写的 `execution`。

## 3. 一次典型任务怎样展开

以下是条件式工作顺序，不是每篇论文必须走完的流水线。

1. **取得来源，确定处理标准和总体预算。** Utility 固定来源字节；Planner 对接 `AgentizationPlan`、`ProcessingProfile`。先记录比较基准和检索限制；不能最后为“有贡献”挑基准。
2. **Paper 清点主张与条件，Review 独立核对范围。** 数学表达要核对量词、假设和对象含义。对本轮处理清单形成 `FrozenScope`。清点不完整时可保存候选，不能伪造范围冻结。现有 `ProofPlan`、`ArgumentSnapshot` 和形式交接都要求精确范围。
3. **按 claim 并行提出论证和寻找依赖。** `proof.expand` 标出缺失的步骤；`dependency.search` 在已有库、明确引用和有界历史检索中寻找候选。共同缺口合并处理；不用等待整篇所有 claim 完成。
4. **独立核对用途，再绑定实际依赖。** `review.reuse` 核对对象、定义、假设、适用范围、证据和形式环境；产生限定用途的复用决定。找到引用或关系获得支持，不自动产生复用许可。
5. **按证明路线自底向上补齐需要的工作。** 已有合格结果直接复用；没有现成记录才对旧来源创建相应任务。探索可以使用明确列出的未证假设，但不得满足原目标的无条件成功门。若某个旧结果已经足以满足所选标准，不要求从公理重新形式化它。
6. **仅对所选形式目标构建交接并调用 Formalization。** 交接由固定的数学记录、范围、论证快照、路线和环境装配。`utility.formal-check` 由独立受控执行边界运行实际检查器；反向解释首轮隔离源目标；`review.alignment` 再比较原文、数学目标和形式声明。来源到数学表达的检查已在前面进行，不是全部拖到最后。
7. **保存所有结果，按需汇总 Delta 与 Reader 输出。** 有失败和开放问题也能保存调查批次。若要正式发布或准入，再安排独立论文审计、机械认证和准入；普通候选入库不自动调用这些正式决定。

新发现条件或承重步骤时，先分类：原文漏提取是提取修订；新增数学假设可能是新命题；新增承重项需要范围修订。保留旧目标与处置，重派受影响任务，不能删掉失败项目来通过原标准。

**下游工作单何时固定：** 上游尚未交付时，只保存后续工作建议及所需产物条件，不填写虚构的 RecordRef。上游结果保存后，调度器按明确的目标/类型/路线选择实际产物，再创建引用这些精确字节的正式 Task。没有产物则等待或保留缺口；出现多个适用候选时，按已固定选择规则选择，或另派比较任务，不能静默取最新一个。`depends_on` 记录工作先决关系，不负责把未来输出自动替换成输入。人工 workflow 样例展示的是已经确定引用后的结构形状，不表示可提前生成未来记录。

## 4. 最小状态机与两道门

状态存在 SQL 运行层；不是数学真值。推荐状态：`PENDING`、`READY`、`RUNNING`、`WAITING`、`DELIVERED`、`FAILED`、`DEFERRED`、`CANCELLED`。

| 事件 | 程序动作 |
|---|---|
| 创建工作单 | 固定任务字节；检查角色、操作、引用形状、依赖和限额，进入 PENDING |
| 先决条件具备、预算可用 | READY；独立审阅还须有无冲突且允许承担任务的执行者 |
| worker 取得租约 | 原子地创建新 attempt，扣留预算，进入 RUNNING |
| 返回 DELIVERED | 校验本次预期产物和回执绑定，原子保存，再满足交付门 |
| 返回 BLOCKED | 保存本次尝试与缺口，任务 WAITING；创建有界后续请求，不占用执行者 |
| 返回 FAILED | 保存失败；仅符合分类和预算的错误可再尝试，否则 FAILED |
| 无进展或预算耗尽 | 保存恢复点，进入 DEFERRED，不声称数学错误或目标已完成 |
| 租约过期 / 进程失联 | 由执行宿主检查实际运行状态；旧租约的迟到结果不能提交；确认可重试才分配新 attempt |

两种 `depends_on.gate`：

- `DELIVERY`：前置工作已经交付任务要求的产物，适合“读到了某个候选”。
- `EVIDENCE`：前置工作已提供目标级、精确版本、所选标准与政策允许的成功证据。必须经独立证据门评估；**不是看到 DELIVERED、ALLOW 字样或非空日志就通过**。

`task.acceptance=EVIDENCE` 必须包含精确 `ProcessingProfile`、`AuthorityPolicy` 和有关目标。目标及证据通过它们和业务记录绑定。v0.1 的离线检查器只检查必要结构，不实现科学门控；未接通的证据门一律不能放行。形式、论证、来源、复用等证据不可互相冒充。

## 5. 并发、复用、重试与预算

1. **重送与复用分开。** 同一 task_id 重送必须字节完全相同，否则拒绝；它不是一次新计算。候选计算缓存键另由版本化模板、操作、brief、target_refs、input_refs、input_artifacts、证明路线、政策/标准、环境、接受要求、允许工具及回避约束共同计算。不能只用论文编号、claim 文本或输入记录集合。同记录用于不同问题、不同代码字节、不同目标或比较方向时不得误命中；新的实际执行拥有新的 attempt ID。语义等价判断不是自动去重规则。
2. **复用计算不复用过期批准。** 只有输入、版本、环境和适用政策匹配时才能复用结果；审阅角色隔离仍须成立。内容相似不是相同数学对象。
3. **写入幂等，拒绝不同内容覆盖同一身份。** 相同 attempt 的相同回执重送可接受；相同身份不同字节必须冲突，不使用最后写入覆盖。共享父任务的输入和每次输出在一次本地事务中绑定。
4. **有限重试。** 网络短暂错误和执行中断可以按退避规则重试；证明反例、假设不匹配不是基础设施错误。无新来源、无新证据、无减少缺口的重复尝试计入无进展限制；不能靠重写答案刷新计数。
5. **全树预算。** 每个任务有 attempts、时间、成本和无进展上限；子任务消耗父计划的预留预算。历史检索另受父计划确定的深度、文献数和范围约束；子任务不能重新获得无限额度。取消释放未用额度，已经使用的成本保留。
6. **影响局部传播。** 某引理变化只使依赖它的相关路线和评估进入重新检查队列；其他 claim 继续。旧评估仍绑定旧字节，不能改写成针对新版本的批准。
7. **租约有代次。** worker 只能提交当前有效 attempt/token；任务取消、重新分配或输入已被替代后，迟到输出可以另存诊断，不得更新当前任务状态。SQL 参考表是存储底座，领取与回收事务仍待实现。

## 6. 例子：纯态引理不能直接承接混态结论

Paper 保存原文 C：“对所有混态成立”。Proof 发现 C 需要 L。Dependency 找到旧论文的 L，但 L 只适用于纯态。

- Review 不批准直接复用，记录具体条件差异。
- Scheduler 让真正依赖 L 的步骤等待，其他步骤继续。
- 可提出三种后续请求：查找混态版本、补推广证明、提出只针对纯态的新命题。第三种不能覆盖原作者的 C。
- 如果已有另一条不使用 L 的证明路线，可以继续那一条，保留原路线的问题。
- 耗尽预算时留下可恢复的缺口；保存批次不要求把所有缺口改成成功。

## 7. 实现时的验收场景

至少覆盖：两篇论文的一次成功用途限定复用、一次条件不匹配拒绝、一次暂停后继续、共同前提缺一不放行、同一任务重复提交不重复记账、上游修订触发局部重审、独立执行者不足时只阻断对应审阅、Neo4j 失效后从指定封存批次重建。

这里列的是未来运行系统验收；当前 `tests/` 的人工反例仅证明离线接口约束，不能代替真实两论文实验。
