# 判定规则与正反例

本文件是 AGENT.md 的规范性附件，与 Paper Agent 的 CONFORMANCE 同构。例子是人工教学材料，不是论文验证结果。每条说明：应发生什么、禁止什么、哪一层能拦住。文中“机器”只指 `check_interfaces.py` 当前实际执行的规则；它覆盖不了数学含义，不要把它读成完整保障。

## E01 目标漂移

情形：原命题“对所有 n”，Lean 声明只写了 n = 3；或把原命题的适用条件搬进证明前提、把结论弱化成容易版本。

- 应发生：视为新命题／新范围／新包；原目标与旧失败保留。
- 禁止：把弱化版本标为原目标；在结论里偷偷加“仅 n = 3”。
- 拦截：人工（R2）＋R5 对齐；机器只看字段格式。

## E02 局部假设外泄

情形：`ASSUME h` 引入局部假设后推出蕴含、反证或分情况结论，但没有显式解除 h。

- 应发生：以允许的规则显式解除，给出 `discharged_context_refs` 与 `rule_evidence_refs`，结论在父范围成立；局部新假设不回写 MathClaim.assumptions。
- 禁止：把临时假设当成最终定理前提；伪造空 context。
- 拦截：机器部分覆盖（DISCHARGE_CONTEXT、INVALID_DISCHARGE_RULE、RULE_EVIDENCE）；解除在数学上是否合法仍靠 R1／R3。

## E03 过度特化

情形：`theorem robustness_ge_one (ρ : Matrix (Fin 8) (Fin 8) ℂ) …` 锁死 3 qubit；下一篇论文做 n qubit 时无法复用。

- 应发生：在写证明前泛化到下游真正需要的范围（如 `Fin (2^n)`），并在 R2 可复用性关确认。
- 禁止：证完再“顺手泛化”并称其为精简。
- 拦截：人工（R2）；机器没有泛化判断能力。

## E04 多余假设

情形：`theorem foo (h1 : P) (h2 : Q) : R`，证明从头到尾没用 h2。

- 应发生：删除 h2，或说明它为何是接口必需；未使用假设警告视为信号。
- 禁止：把多余假设传给下游——每个引用者都被迫构造无用的 Q，负债逐层传染。
- 拦截：机器警告（unused variables／`#lint`）＋R2 人工确认。

## E05 自造平行定义

情形：不用 mathlib／physlib 的既有抽象，自己定义一套 `DensityMatrix`、`StabilizerState`。

- 应发生：复用标准定义；确实必须自造时说明理由与边界。
- 禁止：把“名字相同”“搜到相似引理”“import 成功”当成可以承接目标。
- 拦截：人工（R2／R5）；机器无法判断定义语义。

## E06 sorry 藏在依赖里

情形：当前文件文本没有 `sorry`，但依赖的引理含占位符，或 tactic 失败插入了 synthetic sorry。

- 应发生：对最终目标执行 `#print axioms`，出现 `sorryAx` 即失败。
- 禁止：用 grep 源码代替传递审计。
- 拦截：机器（形式检查与审计入口，见 ENVIRONMENT §3／§4）。

## E07 能编译但不是证明

情形：`native_decide`、`@[implemented_by]`、`@[extern]`、`@[csimp]`（已知绕过 `#print axioms` 的公开 bug）等使不该通过的声明编译通过。

- 应发生：按禁用构造清单扫描源码，使用前显式记录理由；高风险时加做 `.olean` 级重放或外部内核检查。
- 禁止：把“编译成功”当验收；把未运行的独立检查记为通过。
- 拦截：机器（源码扫描为告警，按政策升级为失败）＋R3。

## E08 declaration_map 编造对应

情形：`declaration_map` 字段填得完全合法，但 `node_ref → local_name` 的对应关系是编的。

- 应发生：R3 检查实际代码声明与含义，R4 盲反译，R5 独立对齐；对应表只是被审对象，不是证据本身。
- 禁止：把“表格通过格式检查”当作“对应关系为真”。
- 拦截：当前机器只验格式、路径归属与目标唯一性；语义对应靠 R3–R5（未接入）。

## E09 替换目标 packet 或混入其他路线

情形：Task 指定 packet A，草稿写 B；或声明表引用另一条证明路线、另一修订的节点。

- 应发生：拒绝；packet 必须与 `Task.target_refs` 唯一目标完全一致。
- 禁止：用“输入里可见”当“可以替换”；把可见输入与目标输入混为一谈。
- 拦截：机器（TARGET_PACKET、INVISIBLE_REF、TASK_CONTRACT 与输入族白名单）。

## E10 精简动到陈述

情形：精简轮里顺手泛化了一个假设，或删掉一个“看起来没用”的前提，实际改变了声明含义。

- 应发生：任何陈述、定义或类型实例改动都视为新定理，回 R2 重走声明关与组包；精简轮红线是公理依赖与声明摘要不变。
- 禁止：只重跑编译，就把旧 R4／R5 结论套到新字节上。
- 拦截：机器（声明摘要与 `#print axioms` 比对）＋R2／R4／R5（见 REVIEW §3、§6）。

## E11 环境或库变更沿用旧结论

情形：升级 mathlib、换 toolchain，或更新 registry 条目后，沿用旧环境的检查结论。

- 应发生：新环境＋新 packet＋按 REVIEW §6 重跑受影响检查；历史结论保留原环境归属。
- 禁止：把旧环境的 KERNEL_CHECKED／ALIGNED 迁移为新环境的通过。
- 拦截：人工（REVIEW §6）；报告归属核对属于待实现项。
